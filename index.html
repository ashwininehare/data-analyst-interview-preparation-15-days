Day 1 — SQL Foundations

Topics: SELECT, WHERE, DISTINCT, ORDER BY, LIMIT, LIKE, BETWEEN and NULL.

Example: Find high-balance customers

SELECT Customer_ID, Customer_Name, Balance
FROM Customers
WHERE Balance > 50000
ORDER BY Balance DESC
LIMIT 5;

Important concepts

  • SELECT chooses columns; FROM chooses a table.
  • WHERE filters rows.
  • DISTINCT returns unique selected combinations.
  • IS NULL checks missing values; use = NULL nahi.
  • BETWEEN includes both endpoints.

Interview questions

Q1. What is SQL? SQL is used to query and manage relational database data.

Q2. WHERE vs ORDER BY? WHERE filters rows; ORDER BY sorts the results.

Q3. How do you find missing balances?

SELECT * FROM Customers WHERE Balance IS NULL;

Practice

Write queries to find Nagpur customers, customers younger than 30, unique cities and the top three balances.

Day 2 — JOINs, Subqueries and CTEs

Topics: INNER JOIN, LEFT JOIN, GROUP BY, HAVING, subqueries and CTEs.

INNER JOIN

SELECT c.Customer_Name, a.Account_ID, a.Balance
FROM Customers c
INNER JOIN Accounts a
ON c.Customer_ID = a.Customer_ID;

INNER JOIN returns matching records in both tables.

LEFT JOIN

SELECT c.Customer_ID, c.Customer_Name, a.Account_ID
FROM Customers c
LEFT JOIN Accounts a
ON c.Customer_ID = a.Customer_ID;

LEFT JOIN keeps all rows from the left table, even when no account matches.

CTE example

WITH CustomerTotals AS (
 SELECT Customer_ID, SUM(Amount) AS Total_Amount
 FROM Transactions
 GROUP BY Customer_ID
)
SELECT *
FROM CustomerTotals
WHERE Total_Amount > 100000;

Interview questions

JOIN vs UNION? JOIN combines columns using related rows; UNION stacks compatible result sets vertically.

WHERE vs HAVING? WHERE filters rows before grouping; HAVING filters groups after aggregation.

Practice

Join Customers with Accounts. Find customers with no accounts using LEFT JOIN and WHERE Account_ID IS NULL.

Day 3 — Window Functions, CASE, Dates and NULL

Topics: ROW_NUMBER, RANK, LAG, CASE, date filtering and COALESCE.

Rank transactions per customer

SELECT Customer_ID, Transaction_Date, Amount,
 ROW_NUMBER() OVER(
   PARTITION BY Customer_ID
   ORDER BY Amount DESC
 ) AS rn
FROM Transactions;

CASE example

SELECT Customer_ID, Balance,
 CASE
   WHEN Balance >= 100000 THEN 'High'
   WHEN Balance >= 50000 THEN 'Medium'
   ELSE 'Low'
 END AS Balance_Category
FROM Accounts;

Monthly analysis

SELECT DATE_FORMAT(Transaction_Date, '%Y-%m') AS Month,
       SUM(Amount) AS Total_Amount
FROM Transactions
GROUP BY DATE_FORMAT(Transaction_Date, '%Y-%m')
ORDER BY Month;

COALESCE: returns the first non-NULL value from its arguments.

SELECT Customer_ID, COALESCE(Balance, 0) AS Balance
FROM Accounts;

Interview questions

RANK vs ROW_NUMBER? ROW_NUMBER assigns a unique sequential number; RANK gives tied rows the same rank and leaves gaps afterward.

Why use PARTITION BY? It divides rows into groups for a window calculation without collapsing the rows.

Day 4 — SQL Case Study and Assessment

Scenario: A bank wants to understand transaction activity by branch.

Branch-wise total transaction amount

SELECT Branch_ID, SUM(Amount) AS Total_Amount
FROM Transactions
WHERE Transaction_Date >= '2026-07-01'
  AND Transaction_Date < '2026-08-01'
GROUP BY Branch_ID
HAVING SUM(Amount) > 300000
ORDER BY Total_Amount DESC;

Top five customers by transaction value

SELECT Customer_ID, SUM(Amount) AS Total_Amount
FROM Transactions
GROUP BY Customer_ID
ORDER BY Total_Amount DESC
LIMIT 5;

Assessment tasks

  1. Count transactions by channel.
  2. Calculate average transaction amount by branch.
  3. Find customers with more than ten transactions.
  4. Calculate monthly transaction totals.
  5. Explain one business insight from the result.

Interview tip: Explain the business question, query logic, validation and resulting action.

Day 5 — Advanced Excel

Topics: XLOOKUP, IF, SUMIFS, COUNTIFS, PivotTables, cleaning and Power Query.

Useful formulas

Find a customer:
=XLOOKUP(A2,Customers!A:A,Customers!B:B,"Not Found")

Sum transactions by branch:
=SUMIFS(C:C,A:A,E2)

Count high-value transactions:
=COUNTIFS(C:C,">50000")

Categorise balance:
=IF(B2>=100000,"High","Standard")

Formula ranges and column letters must match your worksheet.

PivotTable workflow

  1. Select the dataset and insert a PivotTable.
  2. Put Branch in Rows.
  3. Put Amount in Values and choose Sum.
  4. Add Channel as a filter or column.
  5. Check totals against the source data.

Interview questions

Why use XLOOKUP? It looks up a key and returns a corresponding value from a specified range.

Why Power Query? It automates repeatable import, cleaning and transformation steps.

Day 6 — Python, NumPy and Pandas

Topics: variables, lists, DataFrames, reading CSV files, missing values, duplicates and groupby.

Load and inspect data

import pandas as pd

df = pd.read_csv("transactions.csv")
print(df.head())
print(df.shape)
print(df.info())
print(df.isnull().sum())

Clean and aggregate

df = df.drop_duplicates()
df["Amount"] = pd.to_numeric(df["Amount"], errors="coerce")

summary = (
    df.groupby("Branch_ID")["Amount"]
      .sum()
      .reset_index(name="Total_Amount")
)
print(summary)

Why errors='coerce'? Invalid numeric values become missing values, which you should investigate before analysis.

Interview questions

What is a DataFrame? A two-dimensional labelled table in Pandas.

Why inspect data before cleaning? To understand row counts, data types, missing values and potential quality issues.

Day 7 — EDA and Business Insights

EDA means Exploratory Data Analysis: understand the data, spot quality problems and discover patterns.

Basic EDA

print(df.describe(include="all"))
print(df.isnull().sum())
print(df.duplicated().sum())

region_sales = (
    df.groupby("Region")["Revenue"]
      .sum()
      .sort_values(ascending=False)
)
print(region_sales)

Visualise a distribution

import matplotlib.pyplot as plt

df["Revenue"].plot(kind="hist", bins=20)
plt.title("Revenue Distribution")
plt.xlabel("Revenue")
plt.show()

Turn findings into insights

  • Observation: one region has lower sales.
  • Investigation: compare customer count, average order value and product mix.
  • Recommendation: test targeted actions after validating the cause.

Interview question: What is the difference between observation and insight? An observation describes a pattern; an insight explains its possible business meaning and supports a decision.

Day 8 — Statistics, Probability and Hypothesis Testing

Topics: mean, median, mode, variance, standard deviation, probability, sampling and hypothesis tests.

  • Mean: arithmetic average; sensitive to outliers.
  • Median: middle value after sorting; more robust to extreme values.
  • Standard deviation: measures spread around the mean.
  • Correlation: measures association, not proof of causation.
  • p-value: how unusual the observed result or more extreme result would be if the null hypothesis were true, under the test assumptions.

Calculate basic statistics

print(df["Amount"].mean())
print(df["Amount"].median())
print(df["Amount"].std())

Hypothesis testing steps

  1. Define the null and alternative hypotheses.
  2. Choose a suitable test and significance level.
  3. Check assumptions.
  4. Calculate the test statistic and p-value.
  5. Interpret the result in business terms.

Interview question: Does correlation prove causation? No. Other variables or coincidence may explain an association.

Day 9 — Power BI, Data Modeling and Star Schema

Topics: Power Query, relationships, fact and dimension tables, star schema, visuals and filter context.

Star schema example

DimCustomer  ──┐
DimDate      ──┼── FactTransactions
DimBranch    ──┘
  • Fact table stores events and numeric measures, such as transaction amount.
  • Dimension tables describe customers, dates, branches or products.
  • Define relationships using reliable keys and appropriate cardinality.
  • Clean data types and remove unwanted rows in Power Query.

First DAX measure

Total Amount =
SUM(FactTransactions[Amount])

Interview questions

Why star schema? It generally simplifies relationships, reporting and measure logic.

Measure vs calculated column? A measure is evaluated according to filter context; a calculated column is computed for each row during data refresh.

Day 10 — DAX Deep Dive, KPIs and Storytelling

Topics: CALCULATE, ALL, DIVIDE, time intelligence and business KPIs.

Revenue percentage of total

Total Revenue =
SUM(Sales[Revenue])

Revenue % of Total =
DIVIDE(
    [Total Revenue],
    CALCULATE(
        [Total Revenue],
        ALL(Sales)
    )
)

CALCULATE evaluates an expression under modified filter context. ALL removes filters from the specified table or columns. Choose the ALL target carefully based on the desired denominator.

Year-over-year thinking

Use a properly related Date table and time-intelligence measures. Confirm the reporting period and whether the comparison is against the same period last year.

Dashboard storytelling

  1. Start with the business question.
  2. Show key KPIs at the top.
  3. Compare trends and segments.
  4. Highlight an actionable finding.
  5. Explain limitations and next steps.

Interview question: What makes a good dashboard? Clear KPIs, accurate measures, useful comparisons, readable design and a clear business action.

Day 11 — End-to-End Data Analyst Case Study

Scenario: Analyse customer transactions and branch performance.

Project workflow

  1. Define the business problem and KPIs.
  2. Inspect data quality, schema and duplicates.
  3. Clean using SQL or Pandas.
  4. Validate totals against source data.
  5. Analyse branch, channel and monthly trends.
  6. Build a Power BI dashboard.
  7. Present insights, limitations and recommendations.

SQL starting point

SELECT Branch_ID,
       COUNT(*) AS Transaction_Count,
       SUM(Amount) AS Total_Amount,
       AVG(Amount) AS Average_Amount
FROM Transactions
GROUP BY Branch_ID
ORDER BY Total_Amount DESC;

Project explanation template

Problem: What decision did the business need to make?

Tools: SQL, Python/Pandas, Excel and Power BI.

My work: Explain the cleaning, analysis, validation and dashboard steps you actually completed.

Impact: State measured results only when you have evidence; otherwise explain the potential benefit.

Day 12 — BFSI Banking Analytics

Topics: CASA, deposits, loan portfolio, NPA, EMI recovery, churn and branch KPIs.

Example: EMI recovery rate

SELECT
  SUM(Recovered_Amount) AS Total_Recovered,
  SUM(EMI_Amount) AS Total_Due,
  100.0 * SUM(Recovered_Amount)
    / NULLIF(SUM(EMI_Amount), 0) AS Recovery_Percent
FROM EMI_Recovery;

Confirm that rows represent the intended EMI population and that partial recoveries and duplicate records are handled correctly.

Useful banking metrics

  • Deposit growth and CASA ratio.
  • Loan outstanding and portfolio mix.
  • Overdue amount and recovery rate.
  • Customer churn rate and product adoption.
  • Branch transaction volume and service turnaround time.

Interview question

How would you investigate increasing overdue EMIs? Segment by branch, loan type, due month and customer risk; validate the data, identify the largest contributors and recommend targeted follow-up with the collections team.

Important: Use the bank's official definitions for NPA, overdue and recovery KPIs.

Day 13 — AI for Data Analysts

Topics: using AI to explain code, generate draft queries, troubleshoot errors and document analysis.

Example prompt

Act as a senior data analyst mentor.
Explain this SQL query in simple English.
Describe each clause, the expected result,
possible NULL or duplicate issues, and how
to validate the output. Do not invent data.

Safe workflow

  1. Use anonymised or synthetic data.
  2. Ask AI for a draft, not unquestioned truth.
  3. Run the code and check the output.
  4. Test edge cases and validate totals.
  5. Explain the final logic in your own words.

Interview question: How do you verify AI-generated SQL? Check schema and business rules, run small tests, compare results with an independent calculation and review security/privacy requirements.
