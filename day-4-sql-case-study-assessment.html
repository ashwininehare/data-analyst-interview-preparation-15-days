Q1 — Easy · 15 Points · 15 Minutes
Day 1 Product Revenue Summary with Quality Flag
Write a single SQL query that shows for each product: total revenue, number of deals, average deal size (rounded to 0 dp), and a quality flag — 'Premium' if avg deal size ≥ 90,000, 'Standard' if ≥ 70,000, else 'Budget'. Filter to only show products with at least 2 deals. Order by total revenue descending.
Scoring: GROUP BY (2) · COUNT + SUM + ROUND(AVG) (4) · CASE WHEN flag (4) · HAVING COUNT≥2 (3) · ORDER BY (1) · Business insight comment (1)
✅ Model Answer
SELECT
    product,
    COUNT(*)                   AS num_deals,
    SUM(revenue)               AS total_revenue,
    ROUND(AVG(revenue), 0)    AS avg_deal_size,
    CASE
        WHEN AVG(revenue) >= 90000 THEN 'Premium'
        WHEN AVG(revenue) >= 70000 THEN 'Standard'
        ELSE                           'Budget'
    END                        AS quality_flag
FROM sales
GROUP BY product
HAVING COUNT(*) >= 2
ORDER BY total_revenue DESC;

-- Expected: Loan (3 deals,290K,Premium) · Insurance (2 deals,195K,Standard)
-- Deposit excluded by HAVING (only 1 deal)
-- Business: Loan is premium-tier product driving 53% revenue — prioritise in Q3 targets
Q2 — Medium · 20 Points · 20 Minutes
Day 1Day 2 Full Rep Performance Report (Including Eve)
Write a SQL query that shows ALL 5 reps (including Eve who has no sales). For each rep show: rep_name, team, target, actual_revenue (0 if no sales), number of deals, % of target achieved (1 dp, 0 if no sales), and a status — 'On Track' if ≥100%, 'At Risk' if ≥80%, else 'Underperforming'. Order by % of target descending.
Scoring: LEFT JOIN from reps (3) · COALESCE on revenue (3) · COALESCE on deals (2) · % of target calculation (3) · CASE WHEN status (4) · All 5 rows present (3) · Business insight (2)
✅ Model Answer
SELECT
    r.rep_name,
    r.team,
    r.target,
    COALESCE(SUM(s.revenue), 0)          AS actual_revenue,
    COALESCE(COUNT(s.sale_id), 0)          AS num_deals,
    ROUND(
        COALESCE(SUM(s.revenue), 0)
        * 100.0 / r.target,
    1)                                     AS pct_of_target,
    CASE
        WHEN COALESCE(SUM(s.revenue),0) >= r.target           THEN 'On Track'
        WHEN COALESCE(SUM(s.revenue),0) >= r.target * 0.8     THEN 'At Risk'
        ELSE                                                         'Underperforming'
    END                                    AS status
FROM reps r
LEFT JOIN sales s ON r.rep_name = s.rep_name
GROUP BY r.rep_name, r.team, r.target
ORDER BY pct_of_target DESC;

-- 5 rows: Alice 115% On Track · Bob 89% At Risk · Carol 63% Under · Dave 50% Under · Eve 0% Under
-- Business: 3/5 reps underperforming — team-level review required before Q3
Q3 — Medium · 20 Points · 20 Minutes
Day 2Day 3 Revenue Rank Within Team Using CTE + Window Function
Using a CTE, write a query that: (1) aggregates total revenue per rep, (2) ranks each rep within their team using DENSE_RANK() ordered by revenue descending, (3) in the final SELECT, shows rep_name, team, total_revenue, team_rank, and labels rank 1 as 'Team Star', rank 2 as 'Solid', else 'Needs Support'. Include all 5 reps (Eve must appear). Order by team, team_rank.
Scoring: CTE correct structure (3) · LEFT JOIN + COALESCE in CTE (3) · DENSE_RANK with PARTITION BY team (5) · CASE WHEN label (4) · 5 rows including Eve (3) · ORDER BY team + rank (2)
✅ Model Answer
WITH rep_totals AS (
    SELECT
        r.rep_name,
        r.team,
        COALESCE(SUM(s.revenue), 0) AS total_revenue
    FROM reps r
    LEFT JOIN sales s ON r.rep_name = s.rep_name
    GROUP BY r.rep_name, r.team
)
SELECT
    rep_name,
    team,
    total_revenue,
    DENSE_RANK() OVER (
        PARTITION BY team
        ORDER BY total_revenue DESC
    )                                  AS team_rank,
    CASE
        WHEN DENSE_RANK() OVER (
                 PARTITION BY team
                 ORDER BY total_revenue DESC) = 1 THEN 'Team Star'
        WHEN DENSE_RANK() OVER (
                 PARTITION BY team
                 ORDER BY total_revenue DESC) = 2 THEN 'Solid'
        ELSE                                                'Needs Support'
    END                                AS performance_label
FROM rep_totals
ORDER BY team, team_rank;

-- Retail: Alice rank1 Team Star · Carol rank2 Solid · Eve rank3 Needs Support
-- SME:    Bob rank1 Team Star · Dave rank2 Solid
-- Business: Eve is rank 3/3 in Retail — HR escalation warranted
Q4 — Hard · 25 Points · 25 Minutes
Day 3 Month-over-Month Revenue with LAG + Trend Flag
Write a SQL query that shows for each month (formatted as 'YYYY-MM'): total monthly revenue, the previous month's revenue using LAG(), the month-over-month % change (1 dp — handle the first month's NULL safely), a trend flag — 'Growth', 'Decline', or 'First Month', and a running cumulative total. Order by month ascending.
Scoring: DATE_FORMAT grouping (2) · LAG() syntax (4) · NULLIF for safe division (4) · MoM % calc correct (4) · CASE WHEN trend flag (4) · Running total ROWS BETWEEN (5) · Business insight (2)
✅ Model Answer
WITH monthly AS (
    SELECT
        DATE_FORMAT(sale_date, '%Y-%m') AS month,
        SUM(revenue)                    AS monthly_revenue
    FROM sales
    GROUP BY DATE_FORMAT(sale_date, '%Y-%m')
)
SELECT
    month,
    monthly_revenue,
    LAG(monthly_revenue, 1)
        OVER (ORDER BY month)               AS prev_month_revenue,
    ROUND(
        (monthly_revenue -
         LAG(monthly_revenue,1) OVER (ORDER BY month))
        * 100.0 /
        NULLIF(LAG(monthly_revenue,1)
                   OVER (ORDER BY month), 0),
    1)                                     AS mom_pct_change,
    CASE
        WHEN LAG(monthly_revenue,1)
                 OVER(ORDER BY month) IS NULL  THEN 'First Month'
        WHEN monthly_revenue >
             LAG(monthly_revenue,1)
                 OVER(ORDER BY month)            THEN 'Growth'
        ELSE                                        'Decline'
    END                                    AS trend_flag,
    SUM(monthly_revenue) OVER (
        ORDER BY month
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    )                                      AS cumulative_revenue
FROM monthly
ORDER BY month;

-- Jan: First Month · Feb: Decline (120K→85K, -29.2%) · Mar: Growth (95K, +11.8%)
-- Apr: Decline (60K) · May: Growth (110K, +83.3%) · Jun: Decline (75K, -31.8%)
-- Cumulative by Jun = 545,000
-- Business: Revenue volatile — no sustained growth trend. May spike = Alice's Insurance deal.
-- CFO needs a stabilisation plan for H2.
Q5 — Hard · 20 Points · 25 Minutes
Day 1Day 2Day 3 Full BFSI Case — Rep Risk + Activity Scorecard
Write a query using 2 chained CTEs that produces a complete rep risk report: CTE 1 — aggregate actual revenue and last sale date per rep (from sales). CTE 2 — join CTE 1 to reps (LEFT JOIN so Eve appears), calculate days_inactive since last sale (NULL = 9999 for Eve), % of target, and assign a risk level — 'Critical' if days_inactive > 60 OR pct_target < 50%, 'Watch' if days_inactive > 30 OR pct_target < 80%, else 'Green'. Final SELECT: all columns + COALESCE last sale date to 'Never Sold'. Order by risk level, days_inactive desc.
Scoring: 2 correct CTEs (4) · LEFT JOIN in CTE 2 (2) · DATEDIFF for days_inactive (3) · COALESCE(9999) for Eve (2) · OR logic in CASE WHEN (4) · COALESCE last_sale (2) · ORDER BY (1) · Business insight (2)
✅ Model Answer
WITH rep_activity AS (
    -- CTE 1: Sales summary per rep
    SELECT
        rep_name,
        SUM(revenue)   AS actual_revenue,
        MAX(sale_date)  AS last_sale_date,
        COUNT(*)        AS num_deals
    FROM sales
    GROUP BY rep_name
),
rep_risk AS (
    -- CTE 2: Join to reps, calculate risk metrics
    SELECT
        r.rep_name,
        r.team,
        r.target,
        COALESCE(ra.actual_revenue, 0)     AS actual_revenue,
        COALESCE(ra.num_deals, 0)           AS num_deals,
        ra.last_sale_date,
        COALESCE(
            DATEDIFF(CURDATE(), ra.last_sale_date),
            9999
        )                                    AS days_inactive,
        ROUND(
            COALESCE(ra.actual_revenue, 0)
            * 100.0 / r.target, 1)          AS pct_target
    FROM reps r
    LEFT JOIN rep_activity ra ON r.rep_name = ra.rep_name
)
SELECT
    rep_name,
    team,
    target,
    actual_revenue,
    num_deals,
    COALESCE(CAST(last_sale_date AS CHAR), 'Never Sold') AS last_sale,
    days_inactive,
    pct_target,
    CASE
        WHEN days_inactive > 60 OR  pct_target < 50  THEN '🔴 Critical'
        WHEN days_inactive > 30 OR  pct_target < 80  THEN '🟡 Watch'
        ELSE                                               '🟢 Green'
    END                                                    AS risk_level
FROM rep_risk
ORDER BY
    CASE risk_level
        WHEN '🔴 Critical' THEN 1
        WHEN '🟡 Watch'    THEN 2
        ELSE                    3
    END,
    days_inactive DESC;

-- Eve: last_sale='Never Sold', days_inactive=9999, pct=0% → 🔴 Critical
-- Dave: pct=50% → borderline, likely 🔴 Critical
-- Carol: pct=63% → 🟡 Watch
-- Bob: pct=89% → 🟡 Watch
-- Alice: pct=115% → 🟢 Green
-- Business: Risk Manager gets ranked action list — Eve + Dave need immediate intervention

📚 Day 1 — Core Patterns

-- Execution order
FROM → WHERE → GROUP BY
→ HAVING → SELECT → ORDER BY

-- HAVING uses aggregate, not alias
HAVING SUM(revenue) > 100000  ✅
HAVING total_rev > 100000     ❌

-- CASE WHEN in SELECT
CASE
  WHEN rev >= 100000 THEN 'High'
  WHEN rev >= 75000  THEN 'Mid'
  ELSE 'Low'
END

-- % contribution
SUM(rev) * 100.0 /
  (SELECT SUM(rev) FROM sales)

-- NULL: IS NULL · IS NOT NULL
-- Strings: single quotes only

-- LEFT JOIN from reps (Eve test)

LEFT JOIN sales s

COALESCE(SUM(s.revenue), 0)

-- Anti-JOIN (no sales reps)

WHERE s.sale_id IS NULL

-- CTE template

    SELECT ... FROM sales ...
),
cte2 AS (
    SELECT ...
    FROM reps r
    LEFT JOIN cte1 c
        ON r.rep_name = c.rep_name
)
SELECT * FROM cte2;

🪟 Day 3 — Window Functions

-- RANK vs DENSE_RANK vs ROW_NUMBER
RANK()        -- 1,1,3 (skip)
DENSE_RANK()  -- 1,1,2 (no skip)
ROW_NUMBER()  -- 1,2,3 (unique)

-- PARTITION BY team (resets per group)
DENSE_RANK() OVER (
    PARTITION BY team
    ORDER BY revenue DESC)

-- LAG + NULLIF (MoM % change)
LAG(rev,1) OVER(ORDER BY month)
(rev - prev)*100.0/
  NULLIF(prev,0)

-- Running total
SUM(rev) OVER(
  ORDER BY month
  ROWS BETWEEN
  UNBOUNDED PRECEDING
  AND CURRENT ROW)

⚖ What Gets You HIRED vs REJECTED in Day 4

❌ Rejected Patterns

  • Q2: INNER JOIN → 4 rows not 5 → Eve missing → data incomplete report
  • Q1: HAVING total_rev > X → alias in HAVING → query fails
  • Q3: ROW_NUMBER instead of DENSE_RANK → no ties handled correctly
  • Q4: No NULLIF in LAG division → #DIV/0 equivalent error
  • Q4: No ROWS BETWEEN in running total → wrong cumulative values
  • Q5: Single CTE instead of 2 chained → logic tangled, hard to read
  • Any Q: No business insight comment → technical pass, interview fail
  • Any Q: Double quotes for strings → silent wrong behaviour

✅ Hired Patterns

  • States approach in comment before first line of SQL — always
  • LEFT JOIN from reps is the FIRST instinct whenever reps is involved
  • COALESCE wraps every revenue and count from a LEFT JOIN — automatic
  • DENSE_RANK for ranking with ties, NULLIF for safe MoM division
  • ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW from memory
  • 2-CTE structure: CTE1 = aggregate, CTE2 = join + enrich, final = label
  • DATEDIFF + COALESCE(,9999) for Eve's inactive days — complete edge case
  • Every query ends with a business insight — "3/5 reps at risk — escalate"
