📖 AI Glossary — 12 Terms Every Analyst Must Know in 2026
GenAI
Generative AI. Creates new content (text, code, images) from patterns learned during training.
e.g. ChatGPT generates SQL; Copilot generates Python
LLM
Large Language Model. Neural network trained on massive text data to predict next tokens.
e.g. GPT-4, Claude, Gemini, IBM Granite
Hallucination
AI confidently produces incorrect or fabricated output — wrong SQL, fake column names.
Fix: always run generated SQL on real data and verify row counts
Prompt
The instruction you give an AI model. Quality of prompt directly determines quality of output.
Role + Context + Task + Constraints + Output Format
RAG
Retrieval-Augmented Generation. AI retrieves relevant documents before generating a response.
Bank chatbot fetches loan policy PDF, then answers customer
Fine-tuning
Re-training a pre-trained model on domain-specific data to improve accuracy in that area.
Fine-tune LLM on bank's internal documents for compliance Q&A
Embedding
Converting text/data into a numerical vector that captures semantic meaning.
Customer complaint → vector → find similar past complaints
Token
Unit of text an LLM processes. ~0.75 words. Long prompts = more tokens = higher cost.
GPT-4: 8K–128K token context window
Bias
AI model produces systematically unfair outputs due to biased training data.
Loan approval model rejects more women if trained on historical biased data
Explainability (XAI)
Ability to explain why an AI model made a specific decision in human-readable terms.
RBI requires explainability for AI-based loan rejection decisions
Copilot
AI assistant embedded in a tool (Excel, Power BI, GitHub) that suggests next actions.
Power BI Copilot generates DAX measures from natural language
watsonx
IBM's AI & data platform. Persistent is an IBM partner — this gets asked directly.
watsonx.ai (models) · watsonx.data (data lakehouse) · watsonx.governance

🎓 Theory Q&A — 5 AI Interview Questions
Q1. What is the difference between Traditional ML and Generative AI? Give one banking example of each.
Hired answer: Traditional ML learns patterns from labelled data to make predictions — e.g., a loan default prediction model trained on historical repayment data outputs "default probability = 78%". Generative AI learns to generate new content — e.g., a GenAI model reads a customer's transaction history and generates a personalised financial advice summary in plain English. Key difference: ML predicts a label or number; GenAI creates new text, code, or content. In BFSI, both are used together — ML for risk scoring, GenAI for customer-facing explanations.
Q2. An AI tool generates a SQL query for your NPA analysis. What are the FIRST 3 things you do before using it in a report?
Hired answer: (1) Run it on actual data — check if the row count matches your expectation. If you have 6 loans and the query returns 9, there's a JOIN issue or hallucinated table name. (2) Check column names — AI often hallucinates column names that don't exist in your schema. Cross-check every column against the actual table DDL. (3) Sense-check the result — does SUM(revenue) = 545,000 as it does in your raw data? If not, the logic has a bug. Rule: AI generates, analyst validates — never the other way around.
Q3. What is Responsible AI? Name 3 principles and give one BFSI example for each.
Hired answer:
(1) Fairness — AI loan approval model must not reject more applicants of a specific gender, religion, or caste. Test: run approval rates across demographic groups — any statistically significant gap = bias issue, reportable to RBI.
(2) Explainability — If AI rejects a loan, the customer has a right to know why. RBI's 2023 guidelines require banks to provide human-readable explanations for AI decisions. SHAP values / LIME are the standard tools.
(3) Data Privacy — Customer PAN, Aadhaar, account number must never be passed as raw text into a public AI model (like ChatGPT). Always mask/anonymise before using any AI tool on real customer data.
Q4. Can GenAI replace a Data Analyst? Answer as if you are in a Persistent Systems panel interview.
Hired answer: No — and here's the precise reason: GenAI is a productivity multiplier, not a replacement. It can generate SQL drafts, write boilerplate Python, and summarise a report in seconds. But it cannot: (1) understand the business context of why a metric moved — an analyst who knows the BFSI domain knows NPA spiked because of Q4 monsoon stress in a region; (2) take accountability for decisions — a bank cannot submit an AI-generated risk report to RBI without a named analyst signing off; (3) handle novel data quality issues that weren't in the training data. The analyst who uses AI well is 3× more productive and therefore more hireable — not replaced.
Q5. Persistent Systems is an IBM partner. What is watsonx and how would a data analyst use it?
Hired answer: watsonx is IBM's enterprise AI and data platform with three components: watsonx.ai — foundation model studio where analysts can prompt, fine-tune, and deploy LLMs on bank data without sending data to a public cloud; watsonx.data — open lakehouse for querying structured + unstructured data at scale; watsonx.governance — AI lifecycle monitoring for bias detection, drift alerts, and regulatory compliance. As a data analyst at Persistent, I would use watsonx.ai to generate SQL/Python drafts from natural language, validate outputs with my domain knowledge, and use watsonx.governance to ensure the churn model we deployed isn't drifting or producing biased outputs over time.

Task 2 — AI-Assisted SQL: Generate → Validate → Fix (40 min)

🎯 Business Ask: Use AI to generate a churn + NPA combined SQL query, then audit it for hallucinations.

Step 2A — AI-Generated Query (typical output with hallucination)

-- ⚠ AI GENERATED — contains 3 bugs, find them before running!
SELECT
    r.rep_name,
    r.team,
    r.target,
    SUM(s.revenue)                  AS total_revenue,
    s.last_activity_date,           -- ❌ BUG 1: column doesn't exist!
    s.credit_score,                 -- ❌ BUG 2: column doesn't exist!
    DATEDIFF(NOW(), s.sale_date)    AS days_inactive,
    CASE
        WHEN SUM(s.revenue) = 0 THEN "Churned"  -- ❌ BUG 3: double quotes!
        ELSE "Active"
    END AS status
FROM reps r
INNER JOIN sales s ON r.rep_name = s.rep_name  -- ❌ BUG 4: INNER misses Eve!
GROUP BY r.rep_name, r.team, r.target
ORDER BY total_revenue;

Step 2B — Validated & Fixed Query (your job as analyst)

-- ✅ FIXED after validation — 4 bugs corrected
SELECT
    r.rep_name,
    r.team,
    r.target,
    COALESCE(SUM(s.revenue), 0)       AS total_revenue,
    MAX(s.sale_date)                    AS last_sale_date,       -- fix BUG 1
    COALESCE(
        DATEDIFF(CURDATE(), MAX(s.sale_date)),
        9999
    )                                   AS days_inactive,
    CASE
        WHEN MAX(s.sale_date) IS NULL
          OR DATEDIFF(CURDATE(), MAX(s.sale_date)) > 90
                                        THEN 'Churned'           -- fix BUG 3
        ELSE 'Active'
    END                                 AS churn_status
FROM reps r
LEFT JOIN sales s ON r.rep_name = s.rep_name   -- fix BUG 4: LEFT not INNER
GROUP BY r.rep_name, r.team, r.target           -- removed hallucinated columns BUG 1+2
ORDER BY days_inactive DESC;

-- Validation check: result must have 5 rows (all reps including Eve)
-- Eve's churn_status = 'Churned', days_inactive = 9999

Step 3A — AI-Generated Python + Your Validation Layer

import pandas as pd
import numpy as np

# ── STEP 1: Load (AI generated this — validate first) ─────────────
df = pd.read_csv('sales.csv')
df['sale_date'] = pd.to_datetime(df['sale_date'])

# ── VALIDATION GATE 1: Shape and schema ───────────────────────────
assert df.shape == (6, 6), f"Expected 6 rows, 6 cols — got {df.shape}"
assert df['revenue'].dtype in ['float64', 'int64'], "Revenue must be numeric"
assert df.isnull().sum().sum() == 0, "No NULLs expected in sales table"
print("✅ Validation Gate 1 PASSED")

# ── STEP 2: Revenue by product (AI generated) ─────────────────────
prod_summary = df.groupby('product')['revenue']\
                 .agg(['sum', 'mean', 'count']).reset_index()
prod_summary.columns = ['product', 'total_revenue', 'avg_revenue', 'num_deals']
prod_summary['pct_of_total'] = (prod_summary['total_revenue'] /
                                    prod_summary['total_revenue'].sum() * 100).round(1)

# ── VALIDATION GATE 2: Total must = 545,000 ───────────────────────
assert prod_summary['total_revenue'].sum() == 545000, "Revenue total mismatch!"
print("✅ Validation Gate 2 PASSED — revenue = 545,000")
print(prod_summary)

# ── STEP 3: Outlier detection (AI generated) ──────────────────────
mean_rev = df['revenue'].mean()
std_rev  = df['revenue'].std()
df['is_outlier'] = (df['revenue'] - mean_rev).abs() > 2 * std_rev
outliers = df[df['is_outlier']]
print(f"\nOutliers (>2 std dev): {len(outliers)} found")
print(outliers[['rep_name', 'product', 'revenue']])

# ── BUSINESS COMMENTARY (YOU add this — AI cannot) ────────────────
loan_pct = prod_summary.loc[
    prod_summary['product']=='Loan', 'pct_of_total'].values[0]
print(f"""
── 3 Business Insights ──────────────────────────────
1. Loan dominates at {loan_pct:.1f}% of revenue — credit risk concentration.
   Action: Diversify into Deposits + Insurance to reduce NPA exposure.
2. Alice drives 42% of total revenue (₹230,000/₹545,000).
   Action: Key-person risk — cross-train Bob as backup for North region.
