Theory DAX Evaluation — Row Context vs Filter Context

Filter Context
Comes from slicers, visual filters, report filters. Affects MEASURES.
-- Slicer: region = "North"
-- Filter context = {North}
SUM(sales[revenue])
-- Returns North revenue only
CALCULATE modifies filter context
Row Context
Active when iterating row-by-row. Used in CALCULATED COLUMNS and iterator functions (SUMX, AVERAGEX).
-- SUMX iterates row by row
SUMX(
  sales,
  sales[revenue] * 1.18  -- GST per row
)
CALCULATE inside iterator converts row context to filter context

DAX Patterns 12 Must-Know Patterns

Pattern 1 — Basic Aggregation
Foundation — every dashboard starts here
Total Revenue   = SUM(sales[revenue])
Avg Revenue     = AVERAGE(sales[revenue])
Deal Count      = COUNT(sales[sale_id])
Unique Reps     = DISTINCTCOUNT(sales[rep_name])
Max Sale        = MAX(sales[revenue])
Pattern 2 — % of Total (VAR + CALCULATE + ALL)
Most asked DAX pattern — asked in every Persistent Power BI interview
Revenue % of Total =
VAR current = SUM(sales[revenue])
VAR total   = CALCULATE(SUM(sales[revenue]), ALL(sales))
RETURN DIVIDE(current, total, 0) * 100
Pattern 3 — Fixed Filter (Ignore Slicer)
Always return a specific segment regardless of user slicer
North Revenue =
CALCULATE(SUM(sales[revenue]), sales[region] = "North")

Enterprise Revenue =
CALCULATE(SUM(sales[revenue]),
    FILTER(reps, reps[team] = "Enterprise"))
Pattern 4 — Achievement % (Safe Division)
KPI card — rep/branch vs target
Achievement % =
VAR achieved = SUM(sales[revenue])
VAR target   = SUM(reps[target])
RETURN DIVIDE(achieved, target, 0) * 100

-- Status flag
Achievement Status =
IF([Achievement %] >= 100, "✅ HIT",
IF([Achievement %] >= 80,  "⚠️ NEAR", "❌ MISSED"))
Pattern 5 — RANKX (Branch / Rep Leaderboard)
Standard dashboard feature — top performers, branch ranking
Rep Rank =
RANKX(
    ALL(sales[rep_name]),          -- rank across ALL reps (ignore filter)
    [Total Revenue],               -- rank by this measure
    ,                              -- value to rank (blank = current context)
    DESC,                          -- highest revenue = Rank 1
    Dense                          -- no gaps in ranking (1,2,2,3 not 1,2,2,4)
)

-- Rank within region only
Rep Rank in Region =
RANKX(
    ALLEXCEPT(sales, sales[region]),  -- keep region filter, remove rep filter
    [Total Revenue],,DESC,Dense
)
Pattern 6 — SUMX / AVERAGEX (Iterator Functions)
Row-level calculation before aggregating — weighted averages, conditional sums
-- Revenue with 18% GST (calculated per row, then summed)
Revenue with GST =
SUMX(sales, sales[revenue] * 1.18)

-- Weighted average revenue (only deals above 10,000)
Weighted Avg =
AVERAGEX(
    FILTER(sales, sales[revenue] > 10000),
    sales[revenue]
)

-- Total revenue per rep × their target weight
Weighted Target Score =
SUMX(
    reps,
    CALCULATE(SUM(sales[revenue])) / reps[target]
)
Pattern 7 — Time Intelligence: MTD / QTD / YTD
Requires a proper Date table marked as Date Table in Power BI
-- Month-to-Date Revenue
Revenue MTD =
CALCULATE([Total Revenue], DATESMTD(dim_date[date]))

-- Quarter-to-Date Revenue
Revenue QTD =
CALCULATE([Total Revenue], DATESQTD(dim_date[date]))

-- Year-to-Date Revenue
Revenue YTD =
CALCULATE([Total Revenue], DATESYTD(dim_date[date]))

-- Fiscal year YTD (India: April–March)
Revenue YTD Fiscal =
CALCULATE([Total Revenue], DATESYTD(dim_date[date], "03-31"))
Pattern 8 — Previous Period Comparison (YoY / MoM)
CFO's first question: "How does this compare to last year?"
-- Same period last year
Revenue SPLY =
CALCULATE([Total Revenue],
    SAMEPERIODLASTYEAR(dim_date[date]))

-- Previous month
Revenue Prev Month =
CALCULATE([Total Revenue],
    DATEADD(dim_date[date], -1, MONTH))

-- Previous quarter
Revenue Prev Quarter =
CALCULATE([Total Revenue],
    DATEADD(dim_date[date], -1, QUARTER))

-- YoY Growth %
YoY Growth % =
VAR curr = [Total Revenue]
VAR prev = [Revenue SPLY]
RETURN DIVIDE(curr - prev, prev, 0) * 100
Pattern 9 — Running Total (Cumulative)
Cumulative revenue — line chart that always goes up
Running Total Revenue =
CALCULATE(
    [Total Revenue],
    FILTER(
        ALL(dim_date[date]),
        dim_date[date] <= MAX(dim_date[date])  -- up to current date
    )
)
Pattern 10 — ALLEXCEPT (Keep One Filter, Remove Others)
% within a category — keeps region filter, removes all others
-- Revenue % within region (each region sums to 100%)
Revenue % Within Region =
VAR current = SUM(sales[revenue])
VAR region_total = CALCULATE(
    SUM(sales[revenue]),
    ALLEXCEPT(sales, sales[region])  -- remove all filters except region
)
RETURN DIVIDE(current, region_total, 0) * 100
Pattern 11 — SELECTEDVALUE (Dynamic Titles)
Dashboard title changes based on slicer selection
-- Dynamic chart title
Chart Title =
"Revenue Dashboard — " &
SELECTEDVALUE(reps[team], "All Teams")
-- If user selects "Enterprise" → "Revenue Dashboard — Enterprise"
-- If nothing selected → "Revenue Dashboard — All Teams"
Pattern 12 — USERELATIONSHIP (Inactive Relationship)
When a table has two date columns — only one relationship can be active
-- Use inactive relationship to filter by a different date column
Revenue by Close Date =
CALCULATE(
    [Total Revenue],
    USERELATIONSHIP(sales[close_date], dim_date[date])
)

Interview Q&A 10 Questions — MNC Level

Q1 What is the difference between SUMX and SUM?
"SUM aggregates a single column — all values summed directly. SUMX is an iterator — it goes row by row, evaluates an expression for each row, then sums the results. Use SUM when the column already has the final value. Use SUMX when you need to calculate something per row first — like revenue × tax rate per transaction before summing."
-- SUM: total revenue column directly
SUM(sales[revenue])

-- SUMX: revenue + 18% GST per row, then total
SUMX(sales, sales[revenue] * 1.18)
Tests: iterator function understanding — advanced DAX Trap: Using SUMX when SUM is sufficient — shows unnecessary complexity
Q2 What is time intelligence in DAX and why does it require a Date table?
"Time intelligence functions like DATEADD, SAMEPERIODLASTYEAR, DATESMTD calculate measures relative to time periods — previous month, same period last year, year-to-date. They require a continuous, gap-free Date table marked as a Date Table in Power BI. Without it, these functions don't know what 'previous month' means — they need a complete calendar to navigate forward and back in time accurately."
Tests: real Power BI modeling experience — Date table is mandatory Trap: Using time intelligence on the raw sales[sale_date] column without a Date table — gives wrong results
Q3 How do you create a Year-over-Year growth measure?
YoY Growth % =
VAR curr = [Total Revenue]
VAR prev = CALCULATE([Total Revenue],
               SAMEPERIODLASTYEAR(dim_date[date]))
RETURN DIVIDE(curr - prev, prev, 0) * 100
"I store current and previous period values in VAR, subtract, divide safely with DIVIDE, multiply by 100 for percentage. SAMEPERIODLASTYEAR returns the equivalent period 12 months ago. The VAR pattern avoids calling [Total Revenue] twice, which is more efficient on large models."
Tests: time intelligence — first question every CFO asks Keywords: SAMEPERIODLASTYEAR · VAR · DIVIDE · period comparison
Q4 What is RANKX and how do you use it for a leaderboard?
Rep Rank =
RANKX(
    ALL(sales[rep_name]),   -- rank across ALL reps
    [Total Revenue],        -- by this measure
    ,                       -- blank = current context
    DESC,                   -- highest = Rank 1
    Dense                   -- no rank gaps (1,2,2,3)
)
"RANKX ranks the current context value against a specified set. ALL(sales[rep_name]) removes the rep filter so every rep is ranked against all others. Dense ranking means tied values share a rank and the next rank is sequential — important for leaderboards where you don't want gaps."
Tests: RANKX is a favourite advanced DAX interview question Trap: Forgetting ALL() — without it, every rep always ranks 1st in their own filtered context
Q5 What is the difference between ALL, ALLEXCEPT, and ALLSELECTED?
FunctionRemovesKeepsUse When
ALL(table)All filters on tableNothingGrand total denominator
ALL(col)Filter on that column onlyOther column filtersRemove one specific filter
ALLEXCEPT(t,col)All filters except specified columnSpecified column% within a category
ALLSELECTED()Column-level filtersSlicer selections% within slicer selection
Tests: nuanced DAX filter manipulation — senior analyst level
Q6 How do you build a KPI card that shows current value, target, and % achievement?
"I create three measures: Total Revenue (SUM), Target Total (SUM from reps table), and Achievement % (DIVIDE with safe fallback). In Power BI, I use a KPI visual or a Card with a reference value. For a richer KPI card, I use a Card visual with [Total Revenue] as the main value, add a subtitle using SELECTEDVALUE for dynamic context, and use conditional formatting to turn the card green above 100% achievement and red below 80%."
Keywords: KPI · conditional formatting · DIVIDE · reference value · dynamic
Q7 What is the VAR pattern and why do you always use it?
-- Without VAR (SUM computed TWICE — inefficient)
DIVIDE(SUM(sales[revenue]),
       CALCULATE(SUM(sales[revenue]), ALL(sales)), 0)

-- With VAR (SUM computed ONCE — stored and reused)
VAR curr  = SUM(sales[revenue])
VAR total = CALCULATE(SUM(sales[revenue]), ALL(sales))
RETURN DIVIDE(curr, total, 0)
"VAR stores an intermediate result and reuses it. Three reasons: performance (expression evaluated once), readability (named variables are self-documenting), and debuggability (I can replace RETURN with VAR name to check intermediate values). On a 1M row BFSI dataset, computing [Total Revenue] twice in every cell of a 50-row table = 100 evaluations vs 50."
Tests: production DAX quality — junior vs senior analyst signal
Q8 How do you tell a data story with a Power BI dashboard?
"A dashboard without a story is just a collection of charts. I structure it as: top row = headline KPIs (total revenue, achievement %, YoY growth) — the 5-second take. Middle section = trends and comparisons — line chart of monthly revenue, bar chart of rep performance vs target. Bottom = detail table for drill-down. Every visual has a clear title that answers a question, not just a label. I can tell the CFO in 30 seconds: revenue is up 18% YoY, North is our strongest region, David is below target and needs attention."
Tests: can you present insights to a non-technical executive — Persistent's clients are banks Trap: Describing visuals instead of insights — "this bar chart shows revenue" vs "North outperforms by 26%"
Q9 How do you create a Date table in Power BI?
-- DAX: Create Date table
dim_date =
CALENDAR(DATE(2026,1,1), DATE(2026,12,31))

-- Add columns
Month Number = MONTH(dim_date[Date])
Month Name   = FORMAT(dim_date[Date], "MMMM")
Quarter      = "Q" & QUARTER(dim_date[Date])
Year         = YEAR(dim_date[Date])
Week Number  = WEEKNUM(dim_date[Date])
"I create a Date table using CALENDAR() in DAX, add Month, Quarter, Year columns, then mark it as a Date Table in Table Tools. Then I relate it to my fact table on the date column. This is mandatory for all time intelligence functions to work correctly."
Trap: Using AUTO date/time in Power BI settings — creates hidden Date tables that conflict with explicit ones
Q10 A CFO asks: "Are we on track to hit annual target?" How do you answer with DAX?
-- YTD Revenue
Revenue YTD =
CALCULATE([Total Revenue], DATESYTD(dim_date[date]))

-- Annualised run rate (project YTD to full year)
Annualised Revenue =
VAR ytd      = [Revenue YTD]
VAR days_elapsed = DATEDIFF(DATE(2026,1,1),
                    TODAY(), DAY)
VAR days_total   = 365
RETURN (ytd / days_elapsed) * days_total

-- On track flag
On Track =
IF([Annualised Revenue] >= [Target Total],
   "✅ ON TRACK", "❌ AT RISK")
"I calculate YTD revenue, divide by days elapsed to get daily run rate, project to full year, compare to annual target. Then surface this as a KPI card with an on-track/at-risk flag. That's what the CFO needs — not just the number but the trajectory."
Keywords: YTD · run rate · projection · annualised · trajectory · DATEDIFF

🎯 5 Things That Get You Hired on Day 10 Topics

  1. Always use VAR pattern. Every DAX measure you write in an interview should use VAR. It signals production experience, not tutorial knowledge.
  2. RANKX without ALL() ranks everything as 1. The most common RANKX bug. Every rep is rank 1 in their own filter context. ALL() is mandatory.
  3. Time intelligence requires a proper Date table. Say this proactively. Interviewers watch for candidates who know this requirement — it separates real Power BI experience from YouTube tutorials.
  4. Dashboard = story, not charts. When presenting a dashboard, lead with the insight: "Revenue is up 18%, David is at risk, North is our growth engine." Not "this bar chart shows revenue by rep."
  5. SUMX for row-level calculations, SUM for column totals. Know when each is appropriate. Using SUMX when SUM suffices shows over-engineering. Using SUM when SUMX is needed gives wrong results.
