SQL Final Q1 — NPA Segmentation + Rep Risk Summary (Hard · 15 pts)
Question: "Write one SQL query using a CTE that: (1) calculates DPD per sale, (2) buckets each sale into Standard/Watchlist/Sub-Standard/NPA, (3) shows per-rep: total revenue, NPA revenue, NPA rate %, and an overall status — 'High Risk' if NPA rate > 30%, else 'Acceptable'." 
WITH dpd_buckets AS (
    SELECT
        rep_name,
        revenue,
        DATEDIFF(CURDATE(), sale_date)           AS dpd,
        CASE
            WHEN DATEDIFF(CURDATE(), sale_date) > 270 THEN 'NPA'
            WHEN DATEDIFF(CURDATE(), sale_date) > 180 THEN 'Sub-Standard'
            WHEN DATEDIFF(CURDATE(), sale_date) > 90  THEN 'Watchlist'
            ELSE                                          'Standard'
        END                                           AS dpd_bucket
    FROM sales
),
rep_risk AS (
    SELECT
        rep_name,
        SUM(revenue)                                  AS total_revenue,
        SUM(CASE WHEN dpd_bucket = 'NPA'
                 THEN revenue ELSE 0 END)           AS npa_revenue,
        ROUND(
            SUM(CASE WHEN dpd_bucket = 'NPA'
                     THEN revenue ELSE 0 END)
            * 100.0 / SUM(revenue), 1)             AS npa_rate_pct
    FROM dpd_buckets
    GROUP BY rep_name
)
SELECT
    r.rep_name,
    rk.total_revenue,
    COALESCE(rk.npa_revenue, 0)                   AS npa_revenue,
    COALESCE(rk.npa_rate_pct, 0)                  AS npa_rate_pct,
    CASE
        WHEN COALESCE(rk.npa_rate_pct, 0) > 30 THEN 'High Risk'
        ELSE                                        'Acceptable'
    END                                            AS risk_status
FROM reps r
LEFT JOIN rep_risk rk ON r.rep_name = rk.rep_name
ORDER BY npa_rate_pct DESC;

-- Eve: no sales → LEFT JOIN keeps her → COALESCE fills 0 → 'Acceptable'
-- Business: Risk Manager gets 1 query → full rep risk ladder
SQL Final Q2 — Month-over-Month Revenue Change (Window · 10 pts)
Question: "Write a SQL query showing each month's total revenue, previous month's revenue (LAG), and the % change month-over-month. Flag months where revenue dropped as 'Decline', increased as 'Growth'." 
WITH monthly AS (
    SELECT
        DATE_FORMAT(sale_date, '%Y-%m')  AS month,
        SUM(revenue)                    AS monthly_revenue
    FROM sales
    GROUP BY DATE_FORMAT(sale_date, '%Y-%m')
)
SELECT
    month,
    monthly_revenue,
    LAG(monthly_revenue) OVER
        (ORDER BY month)            AS prev_month_revenue,
    ROUND(
        (monthly_revenue -
         LAG(monthly_revenue) OVER (ORDER BY month))
        * 100.0 /
        NULLIF(LAG(monthly_revenue)
                 OVER (ORDER BY month), 0),
    1)                              AS mom_change_pct,
    CASE
        WHEN monthly_revenue >
             LAG(monthly_revenue) OVER (ORDER BY month) THEN 'Growth'
        WHEN monthly_revenue <
             LAG(monthly_revenue) OVER (ORDER BY month) THEN 'Decline'
        ELSE 'First Month'
    END                             AS trend_flag
FROM monthly
ORDER BY month;

-- NULLIF prevents divide-by-zero on first row
-- Business: CFO sees month-by-month acceleration or deceleration
⚡ Round 3 — Python Technical (45 min · 25 pts)
Python Final Task — Full EDA + Rep Scorecard + Insight Narrative
Question: "Load sales.csv and reps.csv. Produce a complete rep scorecard (target vs actual, % achievement, status). Find the product with best risk-adjusted value. Write 3 business insights the Regional Head should act on."
import pandas as pd
import numpy as np

# ── Load + Validate ─────────────────────────────────────────────
sales = pd.read_csv('sales.csv')
reps  = pd.read_csv('reps.csv')
sales['sale_date'] = pd.to_datetime(sales['sale_date'])

assert sales.shape == (6, 6),  "Sales row count mismatch"
assert reps.shape  == (5, 4),  "Reps row count mismatch"
assert sales['revenue'].sum() == 545000, "Revenue total mismatch"
print("✅ All validation gates passed")

# ── Rep Scorecard ───────────────────────────────────────────────
actual = sales.groupby('rep_name')['revenue'].sum().reset_index()
actual.columns = ['rep_name', 'actual_revenue']
scorecard = reps.merge(actual, on='rep_name', how='left')
scorecard['actual_revenue'] = scorecard['actual_revenue'].fillna(0)
scorecard['variance']       = scorecard['actual_revenue'] - scorecard['target']
scorecard['pct_target']     = (scorecard['actual_revenue']
                                 / scorecard['target'] * 100).round(1)
scorecard['status'] = scorecard['pct_target'].apply(
    lambda x: '🟢 On Track'   if x >= 100 else
              ('🟡 At Risk'    if x >= 80  else
               '🔴 Underperforming'))
print("\n── Rep Scorecard ──")
print(scorecard[['rep_name','team','target',
                 'actual_revenue','variance','pct_target','status']])

# ── Product Risk-Adjusted Value ─────────────────────────────────
prod = sales.groupby('product')['revenue']\
            .agg(['sum','mean','std','count']).reset_index()
prod.columns = ['product','total','avg','std_dev','deals']
prod['cv'] = (prod['std_dev'] / prod['avg']).round(3)  # coeff of variation
prod['pct'] = (prod['total'] / prod['total'].sum() * 100).round(1)
print("\n── Product Risk-Adjusted Value (lower CV = more consistent) ──")
print(prod.sort_values('cv'))

# ── 3 Business Insights ─────────────────────────────────────────
top = scorecard.loc[scorecard['actual_revenue'].idxmax()]
under_count = (scorecard['status'].str.contains('Under')).sum()
best_prod = prod.sort_values('cv').iloc[0]
print(f"""
── 3 Business Insights for Regional Head ────────────────
INSIGHT 1 — Key-Person Risk:
  {top['rep_name']} contributes {top['actual_revenue']/545000*100:.1f}% of total revenue.
  Action: Cross-train a backup. One resignation = revenue cliff.

INSIGHT 2 — Team Health:
  {under_count}/5 reps are underperforming (<80% of target).
  Action: Immediate 1:1 performance review + incentive review.

INSIGHT 3 — Best Product (Risk-Adjusted):
  {best_prod['product']} has lowest revenue variability (CV={best_prod['cv']:.3f}).
  Action: Push {best_prod['product']} as primary product — predictable revenue,
  lower credit risk vs Loan-heavy portfolio.
""")
⚡ Round 4 — Power BI (30 min · 20 pts)
"Explain your % of Target DAX measure. Why DIVIDE() and not just revenue/target?"
Hired answer: "Eve has 0 sales — her revenue = 0 — but her target is 100,000. If I use SUM(sales[revenue]) / SUM(reps[target]), when the region filter excludes all sales for a rep, the denominator can become 0 and DAX returns an ERROR that breaks every visual it touches. DIVIDE(numerator, denominator, 0) safely returns 0 instead of ERROR when the denominator is 0 or blank. In a live dashboard presented to a Regional Head, a broken visual is a career-ending moment — DIVIDE() prevents that."
"The slicer is filtering by region but the rep performance bar chart is NOT updating. What's the problem and how do you fix it?"
Hired answer (3-step diagnosis):
"(1) Check Model View — is the relationship between sales and regions actually created? If the line is missing, drag region from regions table to sales table — 1-to-Many.
(2) Check relationship direction — it must be single-direction from regions (1-side) to sales (many-side). Bi-directional can cause circular dependency.
(3) Check the slicer field — it must use regions[region], not sales[region]. If the slicer is on the sales table's region column, it filters only that table; if it's on the regions dimension table, it propagates through the relationship and filters all connected visuals. Fix: change slicer field to regions[region]."
⚡ Round 5 — AI + BFSI Rapid Fire (15 min · 20 pts · 4 Qs)
RF1. What is the DPDP Act 2023 and how does it affect a data analyst working on customer data?
Hired (60 sec): "Digital Personal Data Protection Act 2023 — India's first comprehensive data privacy law. For a data analyst: (1) Customer data (name, Aadhaar, PAN, transaction history) can only be processed for the purpose it was collected — you can't repurpose loan application data for a marketing campaign without fresh consent. (2) Data must not be sent to foreign servers without RBI/DPDP compliance clearance — this means never pasting real customer data into ChatGPT. (3) Right to erasure — if a customer requests deletion, you need a data lineage map to know every table where their record exists. As an analyst, I maintain a PII inventory and always mask data before any AI tool interaction."
RF2. Difference between RANK(), DENSE_RANK(), and ROW_NUMBER() — give a BFSI use case for each.
Hired (60 sec): "RANK() — skips numbers after ties. Use: ranking loan officers by revenue — if two are tied at ₹1L, both get rank 1, next gets rank 3. Shows true competition parity.
DENSE_RANK() — doesn't skip. Both get rank 1, next gets rank 2. Use: tiering customers into Platinum/Gold/Silver — no gaps in tiers.
ROW_NUMBER() — unique sequential number regardless of ties. Use: pagination in a report API — 'fetch rows 1–50' of the NPA ledger. Ties broken arbitrarily, so only use when uniqueness is required, not ranking."
RF3. What is model drift and why does it matter for a deployed churn prediction model at a bank?
Hired (60 sec): "Model drift is when a deployed ML model's accuracy degrades over time because the real-world data distribution has shifted away from the training data. For a bank's churn model: if the model was trained on 2022 customer behaviour (pre-inflation spike), by 2026 customers' withdrawal patterns have changed — the model starts missing churn signals it would have caught before. Why it matters: the bank is making retention spend decisions based on a stale model — wasting ₹ on customers who weren't actually at risk, and missing real churners. Fix: monitor prediction accuracy monthly, retrain quarterly. watsonx.governance automates drift detection and alerts the team when accuracy drops below a threshold."
RF4. You find a 20% discrepancy between the Power BI revenue figure and the SQL SUM. Walk me through your diagnosis in 90 seconds.
Hired (structured): "Step 1 — SQL ground truth: SELECT SUM(revenue) FROM sales = 545,000. Step 2 — Power BI measure: open the measure definition — is it SUM(sales[revenue]) or has a CALCULATE with an unintended filter been added? Step 3 — Check relationships: is there a many-to-many or an inactive relationship causing double-counting? Step 4 — Check filters: is there a report-level filter hiding rows? Step 5 — Check data refresh: is Power BI connected to an older version of the CSV? The 20% gap is almost always one of: wrong DAX filter context, double-counted rows due to bad relationship, or stale data. I'd fix at the earliest step that explains the gap and re-validate all three tools agree."
