🎓 Theory Q&A — 5 Interview Questions
Q1. What is the difference between XLOOKUP and VLOOKUP? Why does Persistent expect you to use XLOOKUP?
Hired answer: VLOOKUP only searches left-to-right, requires you to specify a column number (fragile — breaks if columns are inserted), and returns only one value. XLOOKUP searches in any direction (left, right, even horizontal), returns entire rows or columns, has built-in error handling (4th argument), supports wildcard matching, and uses column references instead of numbers so it doesn't break when columns shift. In a BFSI environment where data schemas change, XLOOKUP is far more production-safe. Rule: Never use VLOOKUP in a new workbook — XLOOKUP does everything VLOOKUP does, plus more.
Q2. A colleague sends you a Pivot Table and says "the totals don't match my SQL query." What do you check first?
Hired answer (5-step reconciliation):
(1) Data source range — is the pivot pointing at all 6 rows, or was the range defined when there were only 4 rows? (Right-click → Change Data Source)
(2) Filters active — is there a hidden filter on a field that's excluding rows?
(3) Value field setting — is it showing SUM or COUNT? A common mistake is COUNT of revenue instead of SUM.
(4) Refresh — has the pivot been refreshed after the source data was updated? (Right-click → Refresh)
(5) Cross-check — =SUMIF(Sales!C:C,"Loan",Sales!D:D) vs pivot total — if they match, pivot is correct; if they differ, data source is the issue.
Q3. What is Power Query and why would a data analyst use it instead of manual copy-paste?
Hired answer: Power Query (Get & Transform) is Excel's built-in ETL engine. You connect to a data source (CSV, database, SharePoint), apply transformation steps (remove columns, rename headers, change types, filter rows, merge tables), and the result loads into a sheet. The key advantage: every step is recorded — when next month's data arrives, you click Refresh and all transformations reapply automatically. Manual copy-paste = repeat work every month + human error risk. Power Query = automation + reproducibility. In BFSI, where monthly NPA and revenue reports follow the same structure, Power Query eliminates 80% of manual prep time.
Q4. What is the difference between IF and IFS? When must you use IFS?
Hired answer: IF handles one condition — TRUE branch or FALSE branch. For multiple conditions you have to nest: =IF(x>=100,"A",IF(x>=80,"B","C")) — readable up to 2 levels, unreadable beyond that. IFS evaluates multiple conditions in sequence without nesting: =IFS(x>=100,"A",x>=80,"B",TRUE,"C") — cleaner, easier to audit, supports up to 127 conditions. Rule: use IFS whenever you have 3+ conditions. Always end IFS with a TRUE catch-all to avoid #N/A errors when no condition matches — equivalent to the ELSE in SQL CASE WHEN.
Q5. What is the difference between SUMIF and SUMIFS? When do you use each?
Hired answer: SUMIF — one condition, simple syntax: =SUMIF(range, criteria, sum_range). Use for single-condition totals: "sum all Loan revenue."
SUMIFS — multiple conditions: =SUMIFS(sum_range, range1, criteria1, range2, criteria2, ...). Note the argument order changes — sum_range comes FIRST in SUMIFS, last in SUMIF. Use for multi-condition totals: "sum revenue where product=Loan AND region=North." BFSI example: =SUMIFS(D:D, C:C, "Loan", B:B, "North") — total Loan revenue in the North region. This replaces a filtered Pivot Table for quick dashboard KPIs.

XLOOKUP — Pull Team and Target from Reps Sheet

-- B2: Pull team for each rep =XLOOKUP(A2, Reps!A:A, Reps!B:B, "Not Found") -- lookup_value=A2 · lookup_array=Reps col A · return_array=Reps col B · if_not_found -- C2: Pull target =XLOOKUP(A2, Reps!A:A, Reps!D:D, 0) -- if_not_found=0 so Eve (who exists in Reps) still gets her target value -- D2: Actual revenue (SUMIF from Sales sheet) =SUMIF(Sales!F:F, A2, Sales!D:D) -- sum Sales column D where rep_name (col F) = A2 · Eve returns 0 automatically -- E2: Variance = actual - target =D2 - C2 -- F2: % of target =IFERROR(D2/C2, 0) -- IFERROR handles divide by zero if target is ever blank -- Format F column as Percentage with 1 decimal

VLOOKUP (Legacy — Know It for Interviews)

-- VLOOKUP syntax (still tested in legacy BFSI environments) =VLOOKUP(A2, Reps!A:D, 4, 0) -- lookup_value · table_array · col_index_num(4=target) · 0=exact match -- Weakness: if someone inserts a column in Reps, col 4 changes → wrong result -- XLOOKUP fix: references column directly, not by number -- INDEX-MATCH (enterprise favourite — works in older Excel) =INDEX(Reps!D:D, MATCH(A2, Reps!A:A, 0)) -- MATCH returns row number · INDEX fetches value at that row
Task 3 — IFS · SUMIFS · Conditional Formatting (35 min)

🎯 Business Ask: Add a Status column to the KPI table. Then build a regional summary using SUMIFS. Apply traffic-light conditional formatting.

IFS — Rep Status (On Track / At Risk / Underperforming)

-- G2: Status based on % of target (column F) =IFS( F2 >= 1, "🟢 On Track", F2 >= 0.8, "🟡 At Risk", TRUE, "🔴 Underperforming" ) -- TRUE at end = catch-all (like ELSE in SQL CASE WHEN) -- Without TRUE: formula returns #N/A if no condition matches! -- Expected: Alice 🟢 · Bob 🟡 · Carol 🔴 · Dave 🔴 · Eve 🔴

SUMIFS — Multi-Condition Regional Summary

-- Build a mini summary table with headers: Region | Loan Rev | Insurance Rev | Total -- Loan revenue for North =SUMIFS(Sales!D:D, Sales!B:B, "North", Sales!C:C, "Loan") -- Result: 120,000 -- Insurance revenue for North =SUMIFS(Sales!D:D, Sales!B:B, "North", Sales!C:C, "Insurance") -- Result: 110,000 -- Dynamic version — reference cells instead of hardcoding =SUMIFS(Sales!$D:$D, Sales!$B:$B, $A2, Sales!$C:$C, B$1) -- $A2 = region from col A (locks col, free row) · B$1 = product from row 1 (locks row, free col) -- This lets you drag the formula across the whole summary table! -- COUNTIFS — count deals by region and product =COUNTIFS(Sales!$B:$B, A2, Sales!$C:$C, "Loan") -- AVERAGEIFS — avg deal size for Loan in North =AVERAGEIFS(Sales!$D:$D, Sales!$B:$B, "North", Sales!$C:$C, "Loan")

-- Step 1: Select the Status column (G2:G6) -- Step 2: Home → Conditional Formatting → New Rule → "Format cells that contain" -- Step 3: Cell value contains "On Track" → Fill Green (#92D050) -- Step 4: Repeat — contains "At Risk" → Fill Amber (#FFEB9C) -- Step 5: Repeat — contains "Under" → Fill Red (#FFC7CE) -- Alternative: Use formula-based rule on % column (F2:F6) -- Rule 1: =F2>=1 → Green fill (On Track) -- Rule 2: =F2>=0.8 → Amber fill (At Risk) -- Rule 3: =F2<0.8 → Red fill (Underperforming) -- Data Bars on revenue column (D2:D6): -- Home → Conditional Formatting → Data Bars → Gradient Fill → Green -- Visual bar inside each cell proportional to revenue value

⚖ What Gets You HIRED vs REJECTED on Day 5

❌ Rejected

  • Uses VLOOKUP with a column number — "fragile and outdated" signal
  • IFS formula missing TRUE catch-all — random #N/A errors
  • SUMIFS with sum_range last (SUMIF order) — wrong result silently
  • Pivot showing COUNT instead of SUM — revenue looks like "6" not "545,000"
  • Pivot not refreshed after data change — presents stale numbers
  • Can't explain why Power Query is better than copy-paste
  • No IFERROR on division formula — #DIV/0! visible in stakeholder report
  • Gives raw numbers with no business insight attached

✅ Hired

  • Explains XLOOKUP advantage — "direction-free, no column number, built-in error handling"
  • IFS always ends with TRUE catch-all — "equivalent to ELSE in SQL CASE WHEN"
  • States SUMIFS sum_range comes first — doesn't confuse with SUMIF
  • Pivot: changes Value Field to SUM, formats as currency, adds % of total
  • Explains Power Query "every step is recorded — click Refresh, done"
  • IFERROR wrapped on all division formulas — production-quality workbook
  • Uses $ locking correctly in SUMIFS — formula drags without breaking
  • Business insight per output: "Eve = 0% target — needs HR escalation today"
