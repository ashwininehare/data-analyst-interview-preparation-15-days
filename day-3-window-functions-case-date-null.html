🧬 Window Function Anatomy — The Complete Mental Model

Structure Every Window Function Follows

FUNCTION_NAME() OVER (
    PARTITION BY column_name   -- optional: "for each group"
    ORDER BY     column_name   -- required for LAG/LEAD/RANK/running totals
    ROWS BETWEEN start AND end -- optional: window frame
)

-- PARTITION BY = GROUP BY but rows NOT collapsed (all rows stay visible)
-- ORDER BY inside OVER = different from outer ORDER BY
-- ROWS BETWEEN = how wide the "sliding window" is

-- Common window frames:
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW  -- running total
ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING         -- 3-row moving avg
ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING -- whole partition
RANK()
Assigns rank. Ties get same rank. Next rank skips numbers.
1,1,3 (skip 2)
DENSE_RANK()
Assigns rank. Ties get same rank. Next rank does NOT skip.
1,1,2 (no skip)
ROW_NUMBER()
Unique sequential number. Ties broken arbitrarily.
1,2,3 (always unique)
LAG(col, n)
Returns value n rows BEFORE the current row.
LAG(revenue, 1)
LEAD(col, n)
Returns value n rows AFTER the current row.
LEAD(revenue, 1)
NTILE(n)
Divides rows into n equal buckets (quartiles, deciles).
NTILE(4) = quartile
SUM() OVER()
Running total or partition total without collapsing rows.
Cumulative revenue
AVG() OVER()
Moving average or partition average per row.
3-month moving avg
FIRST_VALUE()
Returns the first value in a window frame.
First sale in region
🎓 Theory Q&A — 5 Interview Questions
Q1. What is the difference between RANK(), DENSE_RANK(), and ROW_NUMBER()? Give a BFSI use case for each.
Hired answer:
RANK() — skips numbers after ties. Example: Two loan officers both at ₹1L → both rank 1, next officer gets rank 3. Use when you want to show actual competitive gaps.
DENSE_RANK() — no skip. Both get rank 1, next gets rank 2. Use when bucketing customers into Gold/Silver/Bronze tiers — no empty tier gaps acceptable.
ROW_NUMBER() — always unique, ties broken arbitrarily by database. Use for pagination in an NPA ledger report — fetching rows 1–50 requires unique row identifiers.
Key rule: if the interviewer asks "how do you get Top-N without duplicates?" — ROW_NUMBER(). If "how do you rank with fair ties?" — RANK() or DENSE_RANK().
Q2. What is PARTITION BY inside OVER()? How is it different from GROUP BY?
Hired answer: Both divide data into groups, but they behave completely differently. GROUP BY collapses rows — you get one output row per group. PARTITION BY does NOT collapse rows — every original row stays in the result, but the window function calculation resets for each partition group.
Analogy: GROUP BY = calculating the team total (1 row per team). PARTITION BY = stamping each employee row with their team's total (all rows stay, each shows team total alongside individual data).
BFSI example: SUM(revenue) OVER (PARTITION BY region) — each sale row shows both its own revenue AND the total revenue for its region. Impossible with GROUP BY alone.
Q3. What does LAG() do and when would you use it in banking analytics?
Hired answer: LAG(column, n) returns the value from n rows before the current row within the defined ORDER BY. It does NOT join to another table — the "previous" value comes from the same result set.
BFSI use cases:
1. Month-over-month revenue change: LAG(monthly_revenue, 1) OVER (ORDER BY month) — previous month's revenue on each row, then calculate % change.
2. DPD escalation: LAG(dpd_bucket) OVER (PARTITION BY account_id ORDER BY month) — was this account in a worse bucket last month? If yes, it's an escalation.
3. Customer balance trend: LAG(balance) OVER (PARTITION BY customer_id ORDER BY txn_date) — detect rapid balance decreases (early churn signal).
Q4. What is NULLIF() and when is it essential? What happens without it?
Hired answer: NULLIF(expr1, expr2) returns NULL if expr1 = expr2, otherwise returns expr1. Its primary use is preventing divide-by-zero errors.
Without it: revenue / target — if target = 0 (like a new rep whose target wasn't set), MySQL returns a division by zero error that crashes the entire query.
With it: revenue / NULLIF(target, 0) — when target = 0, NULLIF returns NULL, so the division returns NULL instead of an error. You can then wrap with COALESCE(..., 0) to replace NULL with 0.
In DAX (Power BI): DIVIDE() does the same job — DIVIDE(revenue, target, 0). Always use DIVIDE() in DAX, never "/".
Q5. What is the difference between COALESCE(), IFNULL(), and ISNULL()? Which should you use in MySQL?
Hired answer:
COALESCE(v1, v2, v3, ...) — returns the first non-NULL value from a list. Works in ALL SQL databases. Accepts multiple arguments. Use this — it's the standard.
IFNULL(expr, replacement) — MySQL-specific. Only 2 arguments. Equivalent to COALESCE with 2 values.
ISNULL(expr) — SQL Server function. In MySQL, ISNULL() is a boolean check (returns 1 if NULL, 0 if not) — it does NOT replace NULL.
Rule: Always use COALESCE() in MySQL interviews — it's portable, multi-argument, and interviewers expect it. Using ISNULL() in MySQL to replace a value is a mistake that signals SQL Server background confusion.
Task 1 — Ranking Functions (40 min)

🎯 Business Ask: The Sales Head wants a revenue leaderboard showing RANK, DENSE_RANK, ROW_NUMBER, and quartile (NTILE) for all reps. Include reps with no sales.

Query 1A — All 4 Ranking Functions Side-by-Side

SELECT
    r.rep_name,
    r.team,
    COALESCE(SUM(s.revenue), 0)              AS total_revenue,
    RANK()        OVER (ORDER BY COALESCE(SUM(s.revenue),0) DESC) AS rnk,
    DENSE_RANK()  OVER (ORDER BY COALESCE(SUM(s.revenue),0) DESC) AS dense_rnk,
    ROW_NUMBER()  OVER (ORDER BY COALESCE(SUM(s.revenue),0) DESC) AS row_num,
    NTILE(4)      OVER (ORDER BY COALESCE(SUM(s.revenue),0) DESC) AS quartile
FROM reps r
LEFT JOIN sales s ON r.rep_name = s.rep_name
GROUP BY r.rep_name, r.team
ORDER BY total_revenue DESC;

-- Expected output (5 rows):
-- Alice  230000  1  1  1  1 (Platinum)
-- Carol   95000  2  2  2  2 (Gold)
-- Bob     85000  3  3  3  2 (Gold) — wait, Bob+Carol both Q2 with 5 reps
-- Dave    60000  4  4  4  3 (Silver)
-- Eve          0  5  5  5  4 (Bronze)
-- Business: quartile 4 = underperformers needing HR attention

Query 1B — Rank WITHIN Each Team (PARTITION BY)

SELECT
    r.rep_name,
    r.team,
    COALESCE(SUM(s.revenue), 0)              AS total_revenue,
    RANK() OVER (
        PARTITION BY r.team
        ORDER BY COALESCE(SUM(s.revenue),0) DESC
    )                                          AS team_rank
FROM reps r
LEFT JOIN sales s ON r.rep_name = s.rep_name
GROUP BY r.rep_name, r.team
ORDER BY r.team, team_rank;

-- Retail team: Alice=rank1, Carol=rank2, Eve=rank3 (within Retail only)
-- SME team: Bob=rank1, Dave=rank2 (within SME only)
-- Business: "Who is the top performer within each team?" — team-level incentives

Task 2 — LAG/LEAD + Running Total (40 min)

🎯 Business Ask: The CFO needs a monthly trend report showing revenue, previous month, MoM % change, and cumulative YTD revenue. Flag months as Growth or Decline.

Query 2A — MoM Revenue Change with LAG()

WITH monthly_rev AS (
    SELECT
        DATE_FORMAT(sale_date, '%Y-%m')  AS month,
        SUM(revenue)                    AS monthly_revenue
    FROM sales
    GROUP BY DATE_FORMAT(sale_date, '%Y-%m')
)
SELECT
    month,
    monthly_revenue,
    LAG(monthly_revenue, 1) OVER
        (ORDER BY month)                  AS prev_month,
    ROUND(
        (monthly_revenue -
         LAG(monthly_revenue, 1)
             OVER (ORDER BY month))
        * 100.0 /
        NULLIF(
            LAG(monthly_revenue, 1)
                OVER (ORDER BY month),
        0),
    1)                                   AS mom_pct_change,
    CASE
        WHEN LAG(monthly_revenue,1)
                 OVER(ORDER BY month) IS NULL    THEN 'First Month'
        WHEN monthly_revenue >
             LAG(monthly_revenue,1)
                 OVER(ORDER BY month)             THEN 'Growth'
        ELSE                                           'Decline'
    END                                  AS trend_flag
FROM monthly_rev
ORDER BY month;

-- NULLIF prevents ÷0 on first row where LAG = NULL
-- Business: CFO sees exactly which months drove growth vs decline

Query 2B — Cumulative Running Total + % of Grand Total

SELECT
    rep_name,
    region,
    product,
    revenue,
    sale_date,
    SUM(revenue) OVER (
        ORDER BY sale_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    )                                    AS running_total,
    ROUND(
        SUM(revenue) OVER (
            ORDER BY sale_date
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        ) * 100.0 /
        SUM(revenue) OVER (),
    1)                                   AS pct_of_total_so_far
FROM sales
ORDER BY sale_date;

-- SUM(revenue) OVER () = grand total (no ORDER BY, no frame = whole table)
-- ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW = classic running total
-- Business: at which sale did we cross 50% of total revenue?

Query 2C — LEAD() for Next Sale Preview

SELECT
    rep_name,
    sale_date,
    revenue,
    LEAD(sale_date, 1) OVER
        (PARTITION BY rep_name ORDER BY sale_date) AS next_sale_date,
    DATEDIFF(
        LEAD(sale_date, 1) OVER
            (PARTITION BY rep_name ORDER BY sale_date),
        sale_date
    )                                               AS days_to_next_sale
FROM sales
ORDER BY rep_name, sale_date;

-- PARTITION BY rep_name → LEAD resets for each rep
-- days_to_next_sale = NULL for each rep's last sale (no next sale)
-- Business: sales velocity — how fast does each rep close their next deal?
Task 3 — CASE WHEN + Date Functions (35 min)

🎯 Business Ask: Segment sales by quarter, flag high/low revenue deals, and calculate rep tenure. Use CASE WHEN inside aggregates.

Query 3A — CASE WHEN Inside SUM() — Conditional Aggregation

SELECT
    rep_name,
    COUNT(*)                                          AS total_deals,
    SUM(CASE WHEN revenue > 100000 THEN revenue ELSE 0 END) AS high_value_rev,
    SUM(CASE WHEN revenue <= 100000 THEN revenue ELSE 0 END) AS low_value_rev,
    COUNT(CASE WHEN product = 'Loan' THEN 1 END)          AS loan_deals,
    COUNT(CASE WHEN product = 'Insurance' THEN 1 END)     AS insurance_deals,
    ROUND(
        SUM(CASE WHEN revenue > 100000 THEN revenue ELSE 0 END)
        * 100.0 / SUM(revenue),
    1)                                                AS high_value_pct
FROM sales
GROUP BY rep_name
ORDER BY high_value_rev DESC;

-- SUM(CASE WHEN) = pivot-style aggregation without actual PIVOT
-- COUNT(CASE WHEN ... THEN 1 END) counts only matching rows (NULLs excluded)
-- Business: which reps close high-value deals vs low-value volume?

Query 3B — Date Functions: Quarter + Tenure + DPD

SELECT
    s.rep_name,
    s.sale_date,
    s.revenue,
    -- Quarter labelling
    CASE QUARTER(s.sale_date)
        WHEN 1 THEN 'Q1 (Jan–Mar)'
        WHEN 2 THEN 'Q2 (Apr–Jun)'
        WHEN 3 THEN 'Q3 (Jul–Sep)'
        ELSE        'Q4 (Oct–Dec)'
    END                                   AS quarter_label,
    -- Rep tenure in months
    TIMESTAMPDIFF(MONTH, r.hire_date, CURDATE()) AS tenure_months,
    -- Days since sale (DPD proxy)
    DATEDIFF(CURDATE(), s.sale_date)    AS days_since_sale,
    -- Month name
    DATE_FORMAT(s.sale_date, '%b %Y')  AS month_year,
    -- Days until year end
    DATEDIFF(DATE_FORMAT(CURDATE(),'%Y-12-31'),
             CURDATE())                 AS days_to_year_end
FROM sales s
JOIN reps r ON s.rep_name = r.rep_name
ORDER BY s.sale_date;

Query 4 — Complete NULL-Safe Rep Audit

SELECT
    r.rep_name,
    r.team,
    r.target,
    -- COALESCE: replace NULL revenue with 0
    COALESCE(SUM(s.revenue), 0)          AS actual_revenue,
    -- COALESCE: replace NULL last sale with 'No Sales'
    COALESCE(CAST(MAX(s.sale_date) AS CHAR), 'No Sales') AS last_sale,
    -- NULLIF + COALESCE: safe % of target
    COALESCE(
        ROUND(
            SUM(s.revenue) * 100.0
            / NULLIF(r.target, 0),
        1),
    0)                                    AS pct_of_target,
    -- IS NULL check for churn status
    CASE
        WHEN MAX(s.sale_date) IS NULL   THEN 'Never Sold'
        WHEN DATEDIFF(CURDATE(),
                     MAX(s.sale_date)) > 90 THEN 'Inactive'
        ELSE                               'Active'
    END                                   AS activity_status
FROM reps r
LEFT JOIN sales s ON r.rep_name = s.rep_name
GROUP BY r.rep_name, r.team, r.target
ORDER BY actual_revenue DESC;

-- Eve: COALESCE(NULL,0)=0 · last_sale='No Sales' · pct=0 · status='Never Sold'
-- All 5 NULL traps handled in one query
-- Business: HR gets complete rep health report including dormant reps

🪟 Window Functions

-- Ranking
RANK()       OVER (ORDER BY rev DESC)
DENSE_RANK() OVER (ORDER BY rev DESC)
ROW_NUMBER() OVER (ORDER BY rev DESC)
NTILE(4)     OVER (ORDER BY rev DESC)

-- Running total
SUM(rev) OVER (
  ORDER BY sale_date
  ROWS BETWEEN
  UNBOUNDED PRECEDING
  AND CURRENT ROW)

-- LAG / LEAD
LAG(revenue, 1)
  OVER (ORDER BY month)
LEAD(revenue, 1)
  OVER (PARTITION BY rep
        ORDER BY sale_date)

-- Grand total (no frame)
SUM(revenue) OVER ()

🔀 CASE WHEN Patterns

-- Simple label
CASE
  WHEN revenue > 100000 THEN 'High'
  WHEN revenue > 50000  THEN 'Mid'
  ELSE 'Low'
END AS rev_band

-- Inside SUM (pivot-style)
SUM(CASE WHEN product='Loan'
         THEN revenue ELSE 0 END)
  AS loan_revenue

-- Inside COUNT
COUNT(CASE WHEN status='NPA'
           THEN 1 END)
  AS npa_count

-- With IS NULL
CASE WHEN col IS NULL
     THEN 'No Data'
     ELSE col END

📅 Date Functions

-- Current date/time
CURDATE()           -- date only
NOW()               -- date + time

-- Difference
DATEDIFF(d1, d2)    -- days
TIMESTAMPDIFF(MONTH, d1, d2)

-- Formatting
DATE_FORMAT(dt, '%Y-%m')   -- 2026-01
DATE_FORMAT(dt, '%b %Y')  -- Jan 2026
DATE_FORMAT(dt, '%d/%m/%Y')

-- Extraction
YEAR(dt)   MONTH(dt)
DAY(dt)    QUARTER(dt)
WEEK(dt)   DAYNAME(dt)

-- Arithmetic
DATE_ADD(dt, INTERVAL 30 DAY)
DATE_SUB(dt, INTERVAL 1 MONTH)

🚫 NULL Functions

-- Replace NULL with value
COALESCE(col, 0)         -- standard ✅
IFNULL(col, 0)           -- MySQL only
ISNULL(col)              -- boolean (not replace!)

-- Prevent divide by zero
rev / NULLIF(target, 0)
-- returns NULL instead of ERROR

-- Check for NULL
WHERE col IS NULL        -- ✅
WHERE col = NULL         -- ❌ never TRUE

-- NULL in aggregates
COUNT(col)   -- skips NULLs
COUNT(*)     -- counts ALL rows
AVG(col)     -- ignores NULLs (÷ non-NULL count)
SUM(col)     -- ignores NULLs (not 0)

-- CONCAT trap
CONCAT_WS(' ', f, l)     -- NULL-safe
CONCAT(f, ' ', l)        -- NULL → whole NULL
