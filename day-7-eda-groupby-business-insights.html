🎓 Theory Q&A — 5 Interview Questions
Q1. What are your 5 steps when you receive a new dataset for EDA?
Hired answer: (1) Load + Validate — read_csv, check shape, assert totals match expected values.
(2) Schema Audit — df.info(), dtypes, fix dates and numerics to correct types.
(3) Missing Value Audit — isnull().sum(), decide: fill with 0/mean/median, or drop.
(4) Distribution + Outlier Check — describe(), value_counts(), Z-score or IQR outlier detection.
(5) Business Insight Generation — groupby aggregations, correlations, top-N, % contributions. Always end with 3 actionable insights — not just numbers.
BFSI context: For a loan portfolio CSV, step 3 is critical — a NULL in EMI amount or loan_amount is a data quality red flag, not just a code issue.
Q2. What is the difference between groupby().agg() and groupby().transform()? When do you use each?
Hired answer: agg() collapses the DataFrame — you get one row per group with the aggregated value. Like SQL GROUP BY. transform() keeps ALL original rows but fills each row with the group's aggregate value — like SQL window function (SUM() OVER (PARTITION BY)). Use agg() when you need a summary table. Use transform() when you need to add a group-level metric back to each row — e.g., adding "team_total_revenue" alongside each rep's individual sale row for % contribution calculations.
Q3. You have a column with 15% missing values. What factors determine whether you fill or drop?
Hired answer: Four factors: (1) % missing — <5% = safe to fill; >30% = question the data source. (2) Type of column — if it's the target variable (e.g., loan_amount), dropping is safer than imputing; for a demographic field, mean/mode fill is acceptable. (3) Business context — in BFSI, NULL in revenue means no transaction, so fillna(0) is correct. NULL in credit_score means unknown risk — filling with mean could mask high-risk customers. (4) Downstream use — if the column feeds a model, imputation strategy affects model bias. Always document which strategy you used and why.
Q4. What is the IQR method for outlier detection? How is it different from Z-score?
Hired answer: IQR (Interquartile Range) = Q3 − Q1. Outlier bounds: lower = Q1 − 1.5×IQR, upper = Q3 + 1.5×IQR. Any value outside these bounds is flagged. Z-score = (value − mean) / std — values with |Z| > 2 or 3 are flagged. Key difference: IQR is robust to outliers themselves — it uses medians, not means, so extreme values don't skew the detection threshold. Z-score uses mean and std which are both pulled by extreme values, making it less reliable when data is heavily skewed. BFSI rule: for revenue data (often right-skewed), prefer IQR. For normally distributed data like credit scores, Z-score is fine.
Q5. What does reset_index() do after groupby? What happens if you forget it?
Hired answer: After groupby().agg(), the groupby column becomes the index — not a regular column. If you forget reset_index(): (1) you can't reference the groupby column in subsequent operations like merges or filters by column name; (2) chaining another operation like sort_values on that column fails or behaves unexpectedly; (3) when you print the result, the column appears as an index row, confusing stakeholders. Rule: always chain .reset_index() immediately after any groupby unless you explicitly need the index form. It converts the index back into a regular column, making the DataFrame behave like a normal table.
Task 1 — Data Cleaning (40 min)

🎯 Business Ask: You receive a "dirty" version of sales data. Clean it completely before any analysis — types, nulls, duplicates, outliers.

Cell 1 — Simulate Dirty Data + Clean It

import pandas as pd
import numpy as np

# ── Load clean data (from Day 6) ─────────────────────────────────
sales = pd.read_csv('sales.csv')
reps  = pd.read_csv('reps.csv')

# ── Simulate dirty data (as you'd get from a client) ────────────
dirty = sales.copy()
dirty.loc[0, 'revenue']   = np.nan          # missing revenue
dirty.loc[2, 'sale_date'] = 'bad-date'       # corrupt date
dirty.loc[4, 'rep_name']  = '  alice  '      # whitespace
dirty = pd.concat([dirty, dirty.iloc[0:1]])    # duplicate row
dirty['revenue'] = dirty['revenue'].astype('object')  # wrong type

print("Dirty shape:", dirty.shape)   # (7, 6) — extra duplicate
print(dirty.isnull().sum())         # revenue: 1 null

Cell 2 — Full Cleaning Pipeline (Run in Sequence)

df = dirty.copy()

# ── STEP 1: Fix column types ──────────────────────────────────────
df['revenue']   = pd.to_numeric(df['revenue'], errors='coerce')
# errors='coerce' → non-numeric → NaN (not ValueError)
df['sale_date'] = pd.to_datetime(df['sale_date'], errors='coerce')
print("After type fix:")
print(df.dtypes)

# ── STEP 2: Strip whitespace from string columns ──────────────────
str_cols = ['region', 'product', 'rep_name']
for col in str_cols:
    df[col] = df[col].str.strip().str.title()
# '  alice  ' → 'Alice' ✅

# ── STEP 3: Handle missing values ────────────────────────────────
print("\nNulls before fill:")
print(df.isnull().sum())

# Rows with NULL sale_date = corrupt → drop
df = df.dropna(subset=['sale_date'])

# NULL revenue = no transaction → fill 0
df['revenue'] = df['revenue'].fillna(0)

print("\nNulls after fix:")
print(df.isnull().sum())  # all zeros

# ── STEP 4: Remove duplicates ─────────────────────────────────────
before = len(df)
df = df.drop_duplicates()
print(f"\nDuplicates removed: {before - len(df)}")  # 1
df = df.reset_index(drop=True)

# ── STEP 5: Outlier detection (IQR method) ───────────────────────
Q1 = df['revenue'].quantile(0.25)
Q3 = df['revenue'].quantile(0.75)
IQR = Q3 - Q1
lower = Q1 - 1.5 * IQR
upper = Q3 + 1.5 * IQR
outliers = df[(df['revenue'] < lower) | (df['revenue'] > upper)]
print(f"\nIQR bounds: ₹{lower:,.0f} – ₹{upper:,.0f}")
print(f"Outliers found: {len(outliers)}")  # 0 for this dataset

# ── STEP 6: Final validation ──────────────────────────────────────
assert df.shape == (5, 6), f"Expected 5 rows after cleaning, got {df.shape}"
assert df.isnull().sum().sum() == 0, "Nulls remain after cleaning!"
print("\n✅ Data cleaning complete. Clean shape:", df.shape)
Task 2 — GroupBy + agg() (40 min)

🎯 Business Ask: Produce multi-aggregate summaries by region and product. Use named agg(). Build a pivot table. Add % contribution column.

Cell 3 — groupby().agg() — Multiple Aggregates in One Call

# ── Reload clean data for this task ──────────────────────────────
sales = pd.read_csv('sales.csv')
sales['sale_date'] = pd.to_datetime(sales['sale_date'])

# ── agg() with named outputs (pandas ≥0.25) ──────────────────────
region_summary = sales.groupby('region').agg(
    total_revenue  = ('revenue', 'sum'),
    avg_revenue    = ('revenue', 'mean'),
    max_revenue    = ('revenue', 'max'),
    num_deals      = ('sale_id', 'count'),
    latest_sale    = ('sale_date', 'max')
).reset_index()

region_summary['avg_revenue'] = region_summary['avg_revenue'].round(0)
region_summary['pct_of_total'] = (
    region_summary['total_revenue']
    / region_summary['total_revenue'].sum() * 100
).round(1)

print(region_summary.sort_values('total_revenue', ascending=False)
                     .to_string(index=False))

# ── Product summary ──────────────────────────────────────────────
product_summary = sales.groupby('product').agg(
    total_revenue  = ('revenue', 'sum'),
    avg_deal_size  = ('revenue', 'mean'),
    num_deals      = ('sale_id', 'count'),
    std_revenue    = ('revenue', 'std')
).reset_index()

product_summary['cv'] = (
    product_summary['std_revenue'] /
    product_summary['avg_deal_size']
).round(3)
# CV = coefficient of variation: lower = more consistent revenue
print("\nProduct Summary:")
print(product_summary.sort_values('total_revenue', ascending=False)
                      .to_string(index=False))

Cell 4 — pivot_table() and transform()

# ── pivot_table: revenue by region AND product ───────────────────
pivot = sales.pivot_table(
    values  = 'revenue',
    index   = 'region',
    columns = 'product',
    aggfunc = 'sum',
    fill_value = 0           # fills NaN with 0 (no sale in that combo)
)
print("Revenue Pivot (Region × Product):")
print(pivot)

# ── transform(): add group total to every row ────────────────────
# Like SQL: SUM(revenue) OVER (PARTITION BY region)
sales['region_total'] = sales.groupby('region')['revenue']\
                              .transform('sum')
sales['pct_of_region'] = (
    sales['revenue'] / sales['region_total'] * 100
).round(1)

print("\nSales with region total + % share:")
print(sales[['rep_name','region','revenue',
             'region_total','pct_of_region']]
      .to_string(index=False))
# transform keeps all 6 rows — each shows its region's total alongside individual revenue
Task 3 — EDA Deep Dive (40 min)

🎯 Business Ask: Run a full EDA on the merged rep scorecard. Find distribution patterns, revenue concentration, team comparison, and monthly trend.

Cell 5 — Full EDA Pipeline

# ── Build full merged dataset ─────────────────────────────────────
rep_agg = sales.groupby('rep_name').agg(
    actual_revenue = ('revenue', 'sum'),
    num_deals      = ('sale_id', 'count'),
    avg_deal       = ('revenue', 'mean'),
    last_sale      = ('sale_date', 'max')
).reset_index()

full = reps.merge(rep_agg, on='rep_name', how='left')
full['actual_revenue'] = full['actual_revenue'].fillna(0)
full['num_deals']      = full['num_deals'].fillna(0).astype(int)
full['pct_target']    = (full['actual_revenue'] / full['target'] * 100).round(1)

# ── EDA 1: Revenue distribution stats ────────────────────────────
print("── Revenue Distribution ──")
print(full['actual_revenue'].describe().round(0))

# ── EDA 2: Revenue concentration (Pareto) ────────────────────────
full_sorted = full.sort_values('actual_revenue', ascending=False)
total_rev = full['actual_revenue'].sum()
top1_pct  = full_sorted.iloc[0]['actual_revenue'] / total_rev * 100
top2_pct  = full_sorted.head(2)['actual_revenue'].sum() / total_rev * 100
print(f"\nTop 1 rep: {top1_pct:.1f}% of total revenue")   # Alice: 42.2%
print(f"Top 2 reps: {top2_pct:.1f}% of total revenue")  # Alice+Bob: 71.6%

# ── EDA 3: Team comparison ────────────────────────────────────────
team_summary = full.groupby('team').agg(
    team_revenue  = ('actual_revenue', 'sum'),
    avg_pct_target= ('pct_target', 'mean'),
    headcount     = ('rep_name', 'count')
).reset_index()
print("\n── Team Comparison ──")
print(team_summary.to_string(index=False))

# ── EDA 4: Monthly revenue trend ─────────────────────────────────
sales['month'] = sales['sale_date'].dt.to_period('M')
monthly = sales.groupby('month')['revenue'].agg(['sum','count']).reset_index()
monthly.columns = ['month','revenue','deals']
monthly['mom_change'] = monthly['revenue'].pct_change().round(3) * 100
print("\n── Monthly Trend ──")
print(monthly.to_string(index=False))

# ── EDA 5: nlargest / nsmallest ──────────────────────────────────
print("\n── Top 3 Deals ──")
print(sales.nlargest(3, 'revenue')[['rep_name','product','revenue','region']]
          .to_string(index=False))
print("\n── Bottom 2 Deals ──")
print(sales.nsmallest(2, 'revenue')[['rep_name','product','revenue']]
          .to_string(index=False))
