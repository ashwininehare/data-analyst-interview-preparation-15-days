🎓 Theory Q&A — 5 Interview Questions
Q1. What is the difference between a pandas Series and a DataFrame? Give a BFSI example of each.
Hired answer: A Series is a one-dimensional labelled array — it has an index and values, but only one column of data. Example: df['revenue'] — a Series of 6 revenue values indexed 0–5. A DataFrame is a two-dimensional labelled data structure — like a table with rows and columns. Example: the full sales table with sale_id, region, product, revenue, sale_date, rep_name. Relationship: a DataFrame is a collection of Series — each column is a Series. When you select one column from a DataFrame you get a Series; selecting two or more columns gives you a DataFrame.
Q2. What does df.info() tell you that df.describe() doesn't? When do you run each?
Hired answer: df.info() shows: column names, non-null count per column, data type (dtype), and memory usage. It tells you WHERE the NULLs are and whether types are correct (e.g., is revenue float64 or object?). Run it first as a schema + quality check. df.describe() shows statistical summary for numeric columns: count, mean, std, min, 25th/50th/75th percentile, max. It tells you the distribution — are there outliers? Is min negative when it shouldn't be? Run it second to understand the data range. Rule: df.info() = schema health. df.describe() = value distribution.
Q3. What is the difference between .loc and .iloc in pandas?
Hired answer: .loc = label-based — uses the actual index label and column name: df.loc[0, 'revenue'] selects the row with index label 0 and the column named 'revenue'. .iloc = integer position-based — uses numeric positions: df.iloc[0, 3] selects the first row, fourth column regardless of labels. BFSI trap: if a DataFrame has been filtered and the index is now 2, 4, 6... — df.loc[0] raises a KeyError, but df.iloc[0] still works. Always reset_index() after filtering if you plan to use .loc with sequential integers.
Q4. What is vectorisation in NumPy and why is it faster than a Python for loop?
Hired answer: Vectorisation means applying an operation to an entire array at once without writing an explicit loop. NumPy operations execute in compiled C code internally — arr * 2 multiplies every element simultaneously at C speed. A Python for loop executes each iteration in the Python interpreter, which has overhead per iteration. For 6 rows the difference is negligible. For 1 million loan records, a NumPy vectorised operation is typically 50–200× faster than an equivalent Python loop. BFSI analogy: calculating interest on 10M accounts — NumPy does it in milliseconds; a for loop takes minutes.
Q5. What is df.merge() and how does it compare to SQL JOIN? What is the default merge type?
Hired answer: df.merge() combines two DataFrames on a common column — it is the pandas equivalent of SQL JOIN. Syntax: sales.merge(reps, on='rep_name', how='left'). The how parameter maps directly to SQL: how='inner' = INNER JOIN, how='left' = LEFT JOIN, how='right' = RIGHT JOIN, how='outer' = FULL OUTER JOIN. Default is 'inner' — just like SQL INNER JOIN, Eve (with no sales) disappears by default. Always specify how='left' when the left DataFrame is your primary entity and you need all rows preserved. Apply fillna(0) after a left merge to handle NaN values.

Cell 4 — Boolean Filtering (SQL WHERE equivalent)

# ── Single condition ────────────────────────────────────────────
high_rev = sales[sales['revenue'] > 90000]
print("High revenue deals:", len(high_rev))  # 3 rows
print(high_rev[['rep_name','revenue','product']])

# ── AND condition (&) — must wrap each in () ─────────────────────
loan_north = sales[
    (sales['product'] == 'Loan') &
    (sales['region']  == 'North')
]
print("\nLoan deals in North:")
print(loan_north)  # 1 row: Alice, 120000

# ── OR condition (|) ────────────────────────────────────────────
north_or_south = sales[
    (sales['region'] == 'North') |
    (sales['region'] == 'South')
]
print("\nNorth or South:", len(north_or_south), "rows")  # 4 rows

# ── isin() — equivalent to SQL IN ───────────────────────────────
key_products = sales[sales['product'].isin(['Loan', 'Insurance'])]
print("\nLoan + Insurance only:", len(key_products), "rows")  # 5 rows

# ── NOT condition (~) — equivalent to SQL NOT IN ─────────────────
no_deposit = sales[~(sales['product'] == 'Deposit')]
print("\nExclude Deposit:", len(no_deposit), "rows")  # 5 rows

# ── sort_values ─────────────────────────────────────────────────

🎯 Business Ask: Calculate key statistical metrics on revenue. Detect outliers using Z-score. Use NumPy for vectorised operations.

Cell 5 — NumPy Arrays and Vectorised Operations

# ── Create NumPy array from revenue column ───────────────────────
rev_arr = np.array(sales['revenue'])
print("Array:", rev_arr)
print("dtype:", rev_arr.dtype)    # float64
print("shape:", rev_arr.shape)    # (6,)

# ── Vectorised operations (no loop needed) ───────────────────────
rev_inr    = rev_arr * 1000                    # convert to paise
rev_above  = rev_arr[rev_arr > 90000]          # boolean mask
rev_pct    = rev_arr / rev_arr.sum() * 100      # % of total

print("\nRevenue % of total:", np.round(rev_pct, 1))
# [22.  15.6 17.4 11.  20.2 13.8]

# ── Key stats using NumPy ────────────────────────────────────────
print("\n── NumPy Statistics ──")
print("Mean:  ", np.mean(rev_arr).round(0))       # 90833
print("Median:", np.median(rev_arr).round(0))     # 90000
print("Std:   ", np.std(rev_arr).round(0))        # 20412
print("Min:   ", np.min(rev_arr))                 # 60000
print("Max:   ", np.max(rev_arr))                 # 120000
print("P25:   ", np.percentile(rev_arr, 25))      # 78750
print("P75:   ", np.percentile(rev_arr, 75))      # 107500

Cell 6 — Z-Score Outlier Detection

# ── Z-score = (value - mean) / std ──────────────────────────────
# Z > 2 or Z < -2 = potential outlier
mean_rev = sales['revenue'].mean()
std_rev  = sales['revenue'].std()

sales['z_score'] = ((sales['revenue'] - mean_rev) / std_rev).round(2)
print(sales[['rep_name', 'revenue', 'z_score']])

# ── Flag outliers ────────────────────────────────────────────────
sales['is_outlier'] = sales['z_score'].abs() > 1.5
outliers = sales[sales['is_outlier']]
print("\nOutliers (|z| > 1.5):", len(outliers))

# ── Revenue band using np.where (vectorised CASE WHEN) ───────────
sales['rev_band'] = np.where(
    sales['revenue'] >= 100000, 'High',
    np.where(sales['revenue'] >= 75000, 'Mid', 'Low')
)
print("\nRevenue Bands:")
print(sales['rev_band'].value_counts())
# High=2 (Alice 120K + 110K) · Mid=3 · Low=1 (Dave 60K)

# ── Business insight ─────────────────────────────────────────────
print(f"""
Business Insight:
  Mean deal size: ₹{mean_rev:,.0f}
  Std deviation:  ₹{std_rev:,.0f}
  Range:          ₹{sales['revenue'].min():,.0f} – ₹{sales['revenue'].max():,.0f}
  Alice's deals ({sales[sales['rep_name']=='Alice']['revenue'].sum():,.0f}) = {sales[sales['rep_name']=='Alice']['revenue'].sum()/545000*100:.1f}% of total
  High-value deals (≥100K): only Alice — key-person revenue risk
""")
Task 4 — Merge + Apply (30 min)

🎯 Business Ask: Merge sales with reps data. Build a rep scorecard with % of target and status label using apply + lambda.

Cell 7 — Merge (LEFT JOIN equivalent)

# ── Aggregate sales per rep ──────────────────────────────────────
rep_sales = sales.groupby('rep_name')['revenue']\
                 .sum()\
                 .reset_index()
rep_sales.columns = ['rep_name', 'actual_revenue']
print("Sales per rep:")
print(rep_sales)

# ── LEFT MERGE: keep all 5 reps including Eve ────────────────────
scorecard = reps.merge(
    rep_sales,
    on='rep_name',
    how='left'                      # how='left' = SQL LEFT JOIN
)

# Fix Eve's NaN revenue → 0 (same as SQL COALESCE)
scorecard['actual_revenue'] = scorecard['actual_revenue'].fillna(0)

print("\nAll 5 reps after left merge:")
print(scorecard[['rep_name','team','target','actual_revenue']])
# Eve: actual_revenue = 0.0 ✅

Cell 8 — Apply + Lambda for Derived Columns

# ── % of target ─────────────────────────────────────────────────
scorecard['pct_target'] = (
    scorecard['actual_revenue'] / scorecard['target'] * 100
).round(1)

# ── Variance: actual - target ────────────────────────────────────
scorecard['variance'] = scorecard['actual_revenue'] - scorecard['target']

# ── Status label using apply + lambda (SQL CASE WHEN) ────────────
scorecard['status'] = scorecard['pct_target'].apply(
    lambda x:
        '🟢 On Track'       if x >= 100 else
        ('🟡 At Risk'        if x >= 80  else
         '🔴 Underperforming')
)

# ── Final scorecard ──────────────────────────────────────────────
print("\n── Rep Scorecard ──")
print(scorecard[['rep_name','team','target',
                 'actual_revenue','pct_target','variance','status']]
      .to_string(index=False))

# ── Business summary ─────────────────────────────────────────────
under = scorecard[scorecard['status'].str.contains('Under')]
print(f"""
Business Insight:
  On Track: {(scorecard['status']=='🟢 On Track').sum()} rep(s)
  At Risk:  {(scorecard['status']=='🟡 At Risk').sum()} rep(s)
  Under:    {len(under)} rep(s) — {', '.join(under['rep_name'].tolist())}
  Action:   Immediate 1:1 review for underperforming reps before Q3
""")

# ── Export for Day 7 EDA ─────────────────────────────────────────
scorecard.to_csv('rep_scorecard.csv', index=False)
print("Saved rep_scorecard.csv")
